# SPEC-036：恢复案例列表与新增/编辑案例的迁移前 UI

状态：Implemented / 已实施并验证
日期：2026-11-10（北京时间）

确认记录：用户于 2026-11-10 回复“继续实施”，批准本文恢复范围。

## 1. 目标与范围

按用户要求，将正式 React 应用的案例列表、新增/编辑案例及其子模块恢复为原 demo 的 UI。保留 React、生产构建、现有 API 和数据合同。以 `551371a` 的父提交 `2e5f54b` 中 `apps/examples/agent-eval/src/web/client/` 的实现为基准，不重新设计页面。

范围包括列表侧栏/筛选/选择/操作、模块新增与编辑弹窗、案例输入/历史/Bad case、判定规则、执行配置，以及编辑页的结果和历史展示。其他页面仅在共用组件受影响时做回归。

## 2. 当前行为与调查依据

已阅读根目录与应用 AGENTS.md、docs/agent-eval-intranet-roadmap.md、SPEC-004/006/035，以及迁移前 app.ts、当前 catalog/page.tsx、case-editor/page.tsx 和 react.css。

- 旧版编辑页为左侧编辑、右侧执行结果与历史记录的工作台；左侧页签顺序为“输入 / 判定规则 / 配置”。当前改为“输入与历史 / 执行配置 / 判定规则 / 历史”，结果与历史失去原有常驻位置。
- 旧版输入、历史、本轮输入分别组织；当前将本轮输入合并进基本信息。需一并核对回放方式、工具配置、Bad case 和判分编辑器的位置、折叠与默认状态。
- 当前列表采用新建的 react-catalog-layout/react-table 样式，与旧版 Layout/Table/CaseTable、BatchBar 等布局结构不同；模块操作、按钮文案和选择工具栏也有偏差。
- SPEC-035 已明确要求保留原有信息结构和视觉规则，此次补齐 UI 一致性。

## 3. 实施方案与接口

1. 从迁移前源码恢复独立参考版本，以同一份确定性案例数据在浏览器记录桌面和窄屏页面，逐项对比。
2. 案例列表复用原有布局、表格列顺序、列宽、按钮层级、模块卡片/操作和批量工具栏；恢复模块说明与“评测当前模块”等对应文案。核对模块新增/编辑弹窗的字段、间距和按钮。
3. 新增与编辑共用原版工作台布局：左侧“输入 / 判定规则 / 配置”，右侧执行结果与历史记录；新建尚未运行时也保留对应占位。窄屏按旧版规则堆叠。
4. 对输入/历史/Bad case、三种回放方式、工具、判分、模型连接/请求头/高级配置逐项对齐原版分组、顺序、折叠状态、提示和控件样式。继续使用 React 状态与组件，不嵌回旧 DOM 应用。
5. 样式尽量限定在案例相关组件，避免影响已修复的评测结果工作台及其他页面。

不改变 API、数据库、保存字段、revision 并发保护、配置覆盖优先级、模型调用与判分语义；不修改 SDK。

## 4. 兼容性与异常处理

- 保留现有路由/深链接、未保存离开提示、保存后刷新、复制/移动/删除、拖选/Shift/跨筛选选择与隐藏选择计数。
- 列表不显示内部案例 ID 或 session_id；详情保留 session_id。Bad case 标记靠近案例名称，回放列只显示回放方式。
- 保留加载、空状态、失败重试、保存冲突和单区域错误提示；请求期间避免重复提交。长错误紧凑展示，长内容换行或局部滚动。
- 不需要调用真实模型即可验证布局；运行中/错误结果通过确定性测试数据复核。

## 7. 实施与验证记录（2026-11-10）

### 实现

- 恢复原版 Layout/CaseTable 模块侧栏、表格、回放/标签标记、筛选选择工具栏和批量操作；案例名称与整行可进入编辑。列表操作恢复为运行/删除，复制与移动通过原有批量入口及编辑页入口提供。
- 新增/编辑恢复 CaseLayout 左右工作台，三个页签依次为输入、判定规则、配置。右侧常驻执行结果与历史；草稿调试直接使用现有增量查询及结果检查器展示，终态刷新历史。
- 输入恢复基本信息、标签芯片、Bad case、可折叠历史消息和独立本轮问题；恢复填入示例入口与工具配置在输入页的位置。
- 判定恢复目标卡片与按需展开检查，保留结束状态等高级设置。配置恢复模型连接、默认请求头、案例覆盖和高级执行分区，移除重复覆盖区域。共享配置组件默认调用保留原布局，案例使用专用布局参数。
- 模块新增/编辑弹窗恢复 560px 宽度、描述多行框、提示及底部取消/保存。标签和请求头复用原有样式，补齐字段标签关联。
