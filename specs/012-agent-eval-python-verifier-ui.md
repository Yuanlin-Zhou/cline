## 1. 目标与范围

让有脚本的用户快速选择或上传并保存；让不会写脚本的用户按需查看模板；让调试脚本的用户进入专用试验证面板。默认规则卡片不展示完整教程、代码、JSON 输入框、完整性矩阵或历史执行表单。

本次只调整 Web 信息结构、布局和交互，保留脚本协议、存储模式、快照、判分语义与现有 API；不修改 SDK，不新增在线代码编辑器、自动安装依赖或重新正式判分。

## 2. 当前行为与问题

`grading-editor.ts` 将选择列表、刷新按钮、始终可见的上传表单、运行环境信息、默认展开的 Python 字段表和完整代码、JS/TS 帮助、JSON 参数、输入要求及试验证组件全部放在规则卡片内。帮助内容挡住后续操作，空参数占空间，语言和版本信息混进选项，按钮之间缺少间距与主次。

`verifier-trial.ts` 将历史选择、刷新、预览、开始和停止平铺；没有独立的输入/结果/日志区域，日志每次点击追加到正文，预览覆盖结果，状态直接显示英文，运行中可改变历史选择，旧结果也容易与新选择混淆。

## 3. 默认规则卡片

示意（状态文案按真实加载结果变化）：

```text
Python 验证脚本                         必须满足  移除

验证脚本
[检查 txt 文件内容                   ▾] [上传 .py]
Python · 用户上传                     环境可用

[试验证]  编写指南  高级设置 ▸
```

- 选择器主要展示显示名称；语言/来源在已选脚本摘要中展示。版本摘要、环境指纹与内部 ID 移到详情，不占默认主视图。
- 空列表显示“还没有脚本，上传一个 .py 文件开始”，可直接上传；列表加载、失败、脚本不可用分别提示并提供就地重试。刷新作为次要图标/文字按钮，有可访问名称。
- 上传通过独立对话框：选择文件、可选名称、简短大小/编码说明、提交；选择前提交不可用，上传中防重复。成功关闭弹窗并自动选中，提示“已选中，保存案例后生效”；失败保留文件与名称，原选择不变。仅对上传 .py 推荐，旧扩展名仍可使用。
- Python 环境就绪用简短状态；不可用时在操作附近显示原因，不藏入高级设置。信任脚本提示放在上传对话框中。
- “高级设置”默认折叠，包含 JSON 参数、必要输入与完整性要求、版本/环境详情。参数非空或要求非默认时显示摘要，提示已有配置；遇到校验错误自动展开并定位，不能因折叠而丢失或跳过校验。
- 对选择的 JS/TS 脚本显示对应语言与兼容指南；Python 专属试验证不可用时解释原因，不让用户提交后才报不支持。注册程序保留原能力。

## 4. 编写指南面板

通过“编写指南”打开有独立滚动区的对话框：

1. “快速开始”：一句入口说明；按“检查最终回复 / 检查文件产物 / 检查会话”选择模板，一次展示一个。提供复制代码、下载 .py，显示需要的运行模式和输入。
2. “可读取的数据”：以执行结果、会话、文件等中文分组，每组给短解释与最小读取片段，技术字段按需展开，避免默认大表。
3. “返回判定”：展示 pass/fail/insufficient 与 checks 的小例子、print 日志用法；解释缺失证据与脚本错误。

JS/TS 兼容帮助只按语言需要展示。完整字段和合同继续由现有文档维护。复制失败提供明确提示，下载文件名与内容保持不变；对话框支持 Escape 关闭、焦点约束与返回触发按钮。

## 5. 试验证面板

规则卡片通过“试验证”打开宽对话框；结果详情的“脚本试验证”使用同一整理后的组件。编辑中的参数/输入要求传入试验证，不要求先保存；历史输入仍是原执行快照，顶部用短提示说明“不调用模型，不修改原结论”。

- 顶部：所选脚本摘要、历史执行选择与次要刷新。历史选项使用中文状态、案例版本和轮次，避免暴露无用内部字段。
- 主操作：开始试验证；执行中替换为停止按钮，禁用本次目标/脚本切换及重复提交。提交时固定 run/item/script/params；结果明确对应这次提交，即使随后改动配置也不重新解释旧结果。
- 内容分为“验证结果 / 输入数据 / 运行日志”。默认结果区域，中文状态及结论清晰突出；逐项检查可展开预期/实际/文件证据。
- 输入区域明确按需加载，提供 JSON 下载；大文本用限制高度的滚动区并标注截断。不会用输入预览覆盖验证结论。
- 日志按需加载并复用已有展示区，不重复追加；环境版本、指纹、输入摘要放“执行详情”，原证据访问仍保留。
- 关闭面板不自动取消后台任务；同一规则页面重开可恢复当前任务与轮询。切换页面时释放轮询并提示任务仍在后台；整页重载后自动恢复不在本次范围。停止需等后台返回终态再允许重试。
- 未保存案例、无已结束历史、无脚本、脚本非 Python、加载失败有明确空态和重试路径；没有有效目标时预览/开始不可用。切换目标清空过期输入预览，标明旧结果属于之前的试验证。

## 6. 布局与兼容

复用当前原生 dialog 与样式体系，可提取复用组件。按钮行使用 flex 与 gap，容器窄时自然换行；代码区横向滚动，不随长 JSON 撑破页面。宽屏对话框设最大宽度与视口内最大高度；窄屏占可用宽度，固定可见标题/关闭入口。

现有 params/required_inputs/require_complete/verifierId/required 等数据原样往返，不自动删掉旧配置、不随模板切换替用户改规则。MongoDB/SQLite 和服务器接口不变。独立 command 规则与其他规则保持现有行为，JS/TS 上传仍可正常保存与执行。

## 7. 验收与实施步骤

1. 整理脚本选择和上传对话框，默认卡片不出现教程代码、字段表、空 JSON 框或历史试验证长表单。
2. 编写指南与高级设置分离；模板切换、复制与下载正常；已配置值保存/重开不丢失。
3. 整理试验证组件的操作状态、输入/结果/日志区域以及任务恢复；原模型调用与结论不变。
4. 浏览器验证 Python 上传成功/失败、列表失败、参数校验、无历史空态、试验证完成/停止/重开、输入下载和日志重复点击；兼容 JS/TS 选择。宽屏及窄屏无溢出，键盘可操作对话框。
5. 运行 Bun 类型检查与相关测试；仅对有行为风险的状态逻辑补充必要测试，既有 Python/Mongo 合同不重复扩大测试范围。更新启动/使用说明与本 spec 的实施记录。
