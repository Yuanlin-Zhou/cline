# SPEC-024：复制案例时编辑配置

状态：Implemented / 已实施
确认记录：2026-10-26 用户回复“继续实施”，批准本方案。
日期：2026-10-26（北京时间）
范围：单案例复制、批量复制、transfer 预览/提交及 SQLite/MongoDB 案例库；不修改 SDK。

## 目标与当前行为

现有复制弹窗只能选择目标模块和重名策略，确认后原样复制并立即保存；有未保存修改时阻止复制。用户希望在复制前调整配置。已阅读内网 roadmap、SPEC-004/005/008/015/019，以及编辑器、transfer、CatalogRepository 和 SQLite/MongoDB 实现。

## 交互方案

- “复制到…”改为分步流程：选择目标 → 编辑副本 → 预览并创建。取消任一步都不保存半成品。
- 单案例复用现有案例编辑能力，预填来源内容，允许修改案例名称/描述、输入、判定规则及运行配置。模型、回放方式、工具、迭代上限、超时、工作区、系统提示词、自定义请求头都可编辑；不要求另存副本后再打开修改。
- 全部字段初始继承原案例及其 defaults，不隐式换成当前全局配置。编辑请求头仍保存环境变量名称，不复制实际凭据。
- 有未保存修改的详情页，复制前明确选择“使用当前编辑内容”或“使用已保存版本”；使用当前内容只影响副本，不先保存或覆盖原案例。校验错误定位到原字段并保留草稿；移动继续遵守原有先保存规则。
- 批量复制显示案例列表和“统一调整运行配置”。统一设置采用显式启用的字段覆盖，未启用字段各自保留；原值不同时显示“各案例不同”，不能因默认空值而清空。
- 批量每个案例可打开独立副本编辑区，沿用同一表单；逐项修改优先于统一覆盖，预览展示最终名称、模块及修改摘要。请求头按完整编辑器校验，不自动猜测合并或删除。
- 最后预览后一次创建所有副本；提交期间禁用重复操作，成功单个打开副本，批量提供目标模块入口。

## 数据与接口方案

- 扩展现有 transfer preview/apply 的 copy items，可选 `draft: { definition, defaults }` 表示副本完整内容；客户端先将统一覆盖和单项编辑解析为最终草稿。省略 draft 保持原样复制语义。
- move 请求不接受 draft，避免顺带改变移动语义。旧 duplicate API 保持兼容。
- 服务端对 draft 使用同一案例解析、模式/判定约束、请求头、工作区绝对路径等校验，禁止仅依赖前端检查。
- 名称冲突按最终 draft.definition.id 计算，继续支持 rename/abort；执行时核对 expectedDefinitionId、源 revision 和最终配置预览指纹，预览后有编辑必须重新预览。
- SQLite 与 MongoDB 复用各自的原子复制事务，所有源与目标和草稿先通过校验再写入；任一失败不创建部分副本。草稿不能修改来源、伪造目标模块或复用内部 ID。
- 副本使用新 UUID、revision=1，无执行历史；来源的配置、revision、已排队任务与历史快照均不变。未修改字段深拷贝完整保留，包括 Python 验证脚本引用及现有覆盖层次。

## 兼容与异常处理

- 没有修改配置的复制结果兼容原操作；跨模块复制不套用目标模块默认值，不复制会话或工作目录产物。
- 来源被修改/删除、目标被归档、名称或预览指纹失效返回 409/404；保留副本草稿，提示重新选择或刷新预览，不自动以新来源覆盖用户编辑。
- 网络结果未知时禁止自动重新提交，沿用现有核对目标模块指引。字段无效显示具体案例与字段；批量能定位到对应草稿。
- 离开有变更的副本编辑流程时给出放弃提示。弹窗/编辑步骤支持键盘、Escape 和焦点返回，窄屏可滚动编辑。
