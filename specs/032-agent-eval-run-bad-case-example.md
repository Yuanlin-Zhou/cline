## 1. 目标与范围

用户希望在截图所示的“评测批次 → 案例结果 → 右侧结果详情”查看对应案例的原始 Bad case 示例，直接与本次最终回复对照。

仅增加已有结果详情的只读展示。不修改案例类型、回放方式、判分、模型请求、MongoDB 合同或 Python 导入接口，不新增数据库字段。

已阅读根/应用 AGENTS、内网 roadmap 和 SPEC-031，检查 createItemInspector、结果详情按需加载和执行快照合同。

## 2. 当前行为

- 评测执行快照保留这些信息，但 createItemInspector 的“结果与断言”页未展示，只能通过输入快照 JSON 查找。
- 批次列表返回轻量摘要，点击选中项后加载完整 RunItem；保持这个性能边界，不能把所有错误输出放回批次列表响应。

## 3. 展示方案

在右侧“结果与断言”页，本次断言/错误提示之后、最终回复之前，增加紧凑区域：

```text
原始 Bad case 示例                           复制
历史错误输出，仅供本次结果对照
┌──────────────────────────────────────────┐
│ 原始错误输出文本 / JSON                   │
└──────────────────────────────────────────┘
错误原因：忽略了项目使用 Bun 的上下文（有才显示）

最终回复
┌──────────────────────────────────────────┐
│ 本次评测实际生成的回复                     │
└──────────────────────────────────────────┘
```

- 默认展示，无须切换新标签页或展开才能看到；普通案例不生成空区域。
- 沿用已确认的间距、字体和紧凑样式；短内容按实际高度显示，长内容最大约 240px 后内部滚动，不撑长整个结果页。
- 输出只读，可复制原始文本；按纯文本安全渲染。JSON 可保留原文，不因格式解析失败阻断本次结果展示。
- reason 非空才显示；不展示可编辑表单或格式选择器，不重复铺开来源平台等元数据。
- 与“本次最终回复”明确分开，历史错误输出不被当成本次失败原因或 Judge 参考答案；本次通过的 Bad case 也展示历史示例。
- 同样用于复用该 inspector 的调试结果；不重新设计其他结果区域。

## 4. 数据来源、兼容性与异常

只读取当前选中执行/重试的 item.snapshot.definition.badCase。不得读取案例库最新定义来补齐历史示例，否则案例被修改、删除或 MongoDB 不可用时会改变历史结果语义。

切换案例或重试记录时，随该条完整 RunItem 更新，避免复用上一条示例。轮询更新不重复累加区域。旧批次快照缺少 badCase 时不展示，即使当前案例库已添加 Bad case 信息也不回填。

复用现有按需加载、加载失败和复制回退处理；数据库结构和列表投影保持不变。无 SQLite/MongoDB 特定分支。运行中可先看历史示例，下方继续显示当前生成进度。

## 5. 验收标准

1. Bad case 的执行结果展示对应快照示例和可选原因，复制得到原始输出；普通案例及缺少该字段的旧快照无空白占位。
2. 原案例被修改/删除后历史示例保持不变，重试/切换案例不串内容；通过、失败和运行中的状态均不将原始示例混入实际回复。
3. 短文本、长文本、JSON、无原因与 HTML 字符串安全显示；桌面与窄屏无页面横向溢出，不出现大量固定留白。
4. 类型检查、构建及有针对性的组件/执行快照回归通过。
5. 按 AGENTS 的强制 UI 复核要求，在真实浏览器走通上述流程，亲自查看桌面与窄屏截图，记录截图与发现/修复的问题后再交付。
