# SPEC-030：MongoDB 取消自定义索引依赖，启动仅检查集合存在

状态：Implemented
日期：2026-10-29（北京时间）
基线：`9866e6c`，`work`。
需求：用户在内网没有建索引权限，要求 MongoDB 不使用自定义索引、启动只检查集合已创建，并更新建集合/修改集合命令。
范围：MongoDB 初始化、启动检查、移除唯一索引后的常规同名处理、相关回归和文档命令。SQLite、SDK、评测执行/判分协议不变。不涉及已取消的 bad case 需求。

## 1. 当前行为与问题

已阅读应用 AGENTS、SPEC-019/026、内网 roadmap，以及 mongo-catalog、mongo-schema、uploaded-verifiers、mongo-prepare、集成测试和现有 TXT 命令。

- MongoCatalog.preflight 主动检查 hello 拓扑、案例/模块集合、四个自定义索引及完整校验器；MongoVerifiers.preflight 另检查脚本集合及校验器。
- prepareMongoCollections 会建立三个案例查询索引和一个模块唯一索引，命令 TXT 也包含相应 createIndexes。
- 缺索引、缺 listIndexes 权限或校验器不完全相等会阻止应用启动，不能满足只建集合的内网部署。
- 部分同名错误直接依赖 MongoDB unique 索引返回 11000；不能只删启动检查却继续宣称原有唯一性保证不变。

## 2. 目标与边界

1. MongoDB 部署无需创建或检查任何自定义索引。
2. 启动阶段只确认案例、模块、脚本三个集合存在，不检查索引、校验器内容或显式检查集群拓扑。
3. 建集合、修改集合、清空重建的原生命令均不包含创建/删除自定义索引。
4. 保持现有正常增删改查、复制、导入和归档流程及应用数据校验；说明没有数据库 unique 约束后的并发边界。

MongoDB 普通集合自动创建的 `_id_` 索引保留，内部 UUID 查询与唯一性继续使用。它不需要用户单独申请 createIndex，也不应通过删除默认索引实现字面上的“所有索引都不要”。本方案不强制查询自然扫描、不使用 hint 禁用数据库已有索引。

## 3. 启动检查

- MongoCatalog 仅通过 listCollections 确认配置的案例、模块集合存在；MongoVerifiers 同样只确认脚本集合存在。可使用 nameOnly 结果，不读取完整集合 options。
- 不调用 listIndexes、collection.options，不对 validator/validationLevel/validationAction/collation 做启动合同比较；移除显式 hello 拓扑断言。
- MongoDB 驱动连接/认证本身仍有正常握手；“只检查集合”不意味着可以跳过网络或认证连接。
- 缺集合时错误明确指出缺失集合名，并提示 DBA 执行建集合命令；连接/授权失败保持错误，不自动建集合、不退回 SQLite。
- 本地运行账号只需原有业务 CRUD 与 listCollections；不再要求 listIndexes 或 DDL 权限。

批量操作仍沿用现有 MongoDB 事务，需要副本集或支持事务的分片集群。本次不将事务改成非原子多次写入。去掉启动拓扑检查不表示 standalone 已获得事务支持；不支持的环境将在事务操作时报错，文档明确此边界。

## 4. 初始化与原生命令

- prepareMongoCollections 移除 createIndexes；mongo:prepare 仍只在明确执行时准备/更新集合校验器，不由启动流程自动调用，成功提示不再宣称索引已准备。
- 原有字段校验器保留：建集合时仍可提供 validator，修改集合通过 collMod 更新。这些属于集合定义，和自定义索引权限分开；运行时不强制存在校验器或完全一致。应用自身的解析、规则、脚本校验保留。
- 更新 create-collections.txt：选择数据库，创建三个集合及原校验器，不包含两条 createIndexes。
- 更新 update-collections.txt：只更新三个集合的校验器，不包含 createIndexes，也不删除已存在索引。
- 更新 rebuild-collections.txt：沿用用户已要求的清空重建形式，三条 drop 后创建三个集合，不重建自定义索引。保留清空数据的明确提示；只交付命令，不实际执行。
- 命令继续使用 MongoDB Shell 可粘贴的 use / db.runCommand，无变量、函数、循环或 TS/JS 文件依赖。
- 已有自定义索引不自动删除；系统不再依赖或管理它们。无 dropIndex 权限的账号不需要额外操作。
- 同步 STARTUP、MongoDB 指南、管理员命令说明；去掉“缺自定义索引不能启动”的旧描述。其他环境变量和集合名字保持。

## 5. 名称约束与兼容性

- 保留现有导入 skip/version、复制自动命名、修订号 CAS 与模块 writeVersion 协调，不取消这些保护。
- 对此前纯粹依赖 unique 索引的常规模块创建/改名、案例创建/改名/恢复等补充应用层活动名称冲突检查，正常重名返回原有 409 语义，归档名称仍可重用。
- 案例写入可复用已有模块 touch 事务进行同模块操作协调；不引入新集合、新的分布式锁或默认索引。
- **不宣称应用查询能替代数据库唯一约束**：尤其多实例模块创建/跨模块改名或直接外部并发写入，没有 unique 索引时仍可能产生同名活动记录；应用常规检查可改善交互，无法兜底所有并发写入。已有索引若仍保留，数据库仍会执行该约束。
- `_id_` 的数据库唯一性、案例 revision 更新保护、脚本 token 并发保护不变。
- 无新必填字段、无业务文档迁移。原来有索引的库和新建无自定义索引的库都能启动；SQLite 行为不变。

## 6. 异常与性能

集合存在但数据不符合应用合同，仍在实际读取/写入时定位报错；启动不扫描所有案例去替代校验器。过旧或更严格的数据库校验器仍可能拒绝写入，此时提示更新集合，不把写入失败伪装为成功。

无自定义索引时部分筛选/排序会扫描集合；延续已有摘要投影与按需详情，不退回读取全部历史正文。此次不新增分页/搜索架构，不承诺大规模数据查询性能与有索引时一致。

## 7. 验收

1. 只有三个集合、无四个自定义索引时可通过启动检查；没有 listIndexes 权限也可以启动。
2. 启动仅检查集合存在，不读取 options 或比较 validator，不显式检查 hello 拓扑；模拟上述接口被拒绝仍不影响集合检查。
3. 缺任一集合错误明确，认证/连接失败仍阻止启动，不发生隐式 DDL。
4. 初始化及三份原生命令不含 createIndex/createIndexes/dropIndex/dropIndexes；新集合仍有 MongoDB 自动 `_id_`。
5. 正常 CRUD、同名冲突、归档恢复、导入/复制、版本保护回归通过，文档明确并发唯一性边界。
6. 类型检查、构建、相应 Mongo 仓库/启动/初始化测试与资源管理回归；没有真实 MongoDB 时明确区分模拟与实际集群验证。
