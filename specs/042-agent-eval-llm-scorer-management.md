# SPEC-042：LLM 评分器管理与案例多评分器

状态：Implemented / 已实施
确认记录：用户于 2026-11-17 回复“继续实施”，批准本方案。
日期：2026-11-17

## 1. 目标与当前行为

新增可复用 LLM 评分器管理，每个案例可选择一个或多个评分器，分别评价同一次执行的结果/轨迹。已阅读 AGENTS、内网 roadmap、SPEC-025/038/039、judge-schema、judging/config/types/summary/scores、judging API 及运行提交/导出入口。

当前 definition.llmJudge、result.llmJudge 都是单对象；全局 Judge 配置只是模型默认值，没有可管理的评分器实体。多选需要贯通合同、持久化、执行、试评分、统计和导出。本方案取代 SPEC-025 的单评分器限制，不修改 SDK。

## 2. 管理与案例交互

- 顶部增加“LLM 评分器”入口，Ant Design Table 展示名称、说明、模型、评分目标、版本与启用状态。支持新增、编辑、复制、停用/启用和删除。
- 每个评分器配置名称、说明、Provider/模型/Base URL/密钥环境变量/请求头、评分标准、结果/轨迹目标、超时与输入上限，以及“影响通过结果”和及格分的默认值。评分标准作为现有 rubric 传递，固定系统提示词和结构化输出合同保留，不允许配置工具执行。
- 案例判定规则中多选评分器，按选择顺序显示配置摘要。参考答案与产物路径属于案例；每个已选评分器可覆盖参考答案、产物路径、是否影响通过及及格分。共享参考答案为默认，各评分器可使用不同标准评价同一结果。
- 可移除、停用某个案例绑定；停用保留配置。没有评分器时允许保持现有无 LLM 评分行为。
- 管理端编辑生成新 revision。案例保存评分器配置快照及来源版本；已有案例显示“有新版本”并提供显式更新，不静默改变案例或历史执行。停用评分器阻止新增选择，已有快照仍可执行并标注来源已停用。
- 被案例引用的评分器禁止硬删除并列出引用，建议停用；未引用可确认删除。历史结果依靠冻结快照独立读取。

## 3. 数据与接口

新增 scorer 实体：id、name、description、revision、enabled、config、createdAt、updatedAt。SQLite 与 MongoDB 均实现存储和校验。

新增 /api/llm-scorers 列表/创建、/:id 读取/更新/删除及复制操作；更新携带 revision，冲突返回 409 并保留草稿。服务端校验字段、模型配置及引用约束。

案例增加 llmJudges 数组，每项含稳定 bindingId、scorerId/sourceRevision、名称、有效配置快照。结果增加 llmJudges 数组，每项含对应 bindingId、来源名称/版本及现有 JudgeResult。绑定 ID 用于关联，名称仅用于展示。重复选择同一评分器时提示已选择。

旧 llmJudge 在读取/编辑时映射成一个“原案例评分配置”绑定，不自动创建公共评分器；允许用户另存为评分器。旧数据与旧结果继续可读，保存转换为新结构；禁止新旧字段同时配置以免重复执行。同步 schema、复制、版本、JSON 编辑、导入/导出与 CLI 合同。导出包含完整快照；跨环境导入来源不存在时作为独立快照保留，可重新绑定本地评分器，不依赖原库 ID 才能运行。

## 4. 执行、快照和结论

1. 提交前校验全部启用绑定并冻结配置；已保存案例使用其快照，评分器管理变更不追溯更新。参考答案等评分配置从被测 worker 输入剥离。
2. 被测案例只执行一次，证据归档一次；各评分器独立读取同一份冻结证据，按各自 targets/文件构造输入。首期按绑定顺序串行评分，沿用案例级并发控制，不额外放大模型请求并发。
3. 每个评分器保存独立状态、分数、理由、证据、模型/配置/输入哈希、耗时和用量。一个评分器错误不阻止其余评分器；取消停止当前请求并将尚未开始的评分标记 cancelled。
4. 默认只评分，不改变确定性结论。开启“影响通过结果”的评分器必须全部达到各自阈值；任一已评分但未达标则失败，无已知失败而必要评分错误/信息不足时为无法判定。已有执行错误、取消和确定性失败不被评分覆盖；沿用原状态优先级。
5. 不默认把不同评分器分数求平均作为最终分数，也不增加投票/权重配置。报告按评分器来源版本和有效配置分组统计，显示应评分/已评分/错误数量；费用包含所有实际评分请求，重试不漏计。
6. 执行详情逐项展示评分器结果。试评分可选择一个或多个评分器，使用历史证据，仅产生独立试评分记录，不修改正式结论。预览和正式输入接口增加 bindingId；多个绑定时不默认取第一个。
7. JSON/CSV 导出包含每个评分器身份及结果；保留旧记录读取，新增明细导出防止把多个评分结果压成单个值。重复评测报告同步适配。

## 5. 异常与兼容

- 沿用现有独立 Judge 模型请求和凭据环境变量机制，不新增公网服务依赖；Judge 不使用被测工具权限。
- 无效配置在保存/运行预检明确定位到评分器；缺少凭据、超时、非法输出、材料不足分别记录，不伪装成低分或零分。
- 评分器删除/更新与案例绑定保存需校验引用及 revision，避免产生悬空管理引用。历史快照不依赖管理实体存在。
- 前端异步提交防重，失败保留表单；停用/删除/版本更新有明确提示。CLI 无管理库时仍能运行配置完整的独立快照。

## 7. 实施与验证（2026-11-17）

已实现公共评分器 CRUD/复制/启停、revision 冲突、引用删除保护、案例多选/独立快照/显式更新、旧单配置兼容；执行器一次归档后逐个评分，记录数组并聚合必要判定。历史试评分可选择多个评分器，分别预览和确认，保留评分器身份。报告分组及 JSON/CSV 导出覆盖全部评分器；CSV 每个执行/评分器一行。配置模板不保存案例参考答案与产物路径，新绑定默认复用第一个已有绑定的参考答案，也可分别修改。

SQLite 已实际验证；MongoDB 新增 agent_eval_llm_scorers 及案例数组合同，同步管理员 create/update/rebuild 命令和文档。运行服务不自动执行建集合操作。案例与评分器写入在本地服务内串行化；未验证多个服务实例同时写入同一 MongoDB 的跨实体删除竞态。

验证：前后端 typecheck、生产 Vite 构建通过；全量 11 项浏览器回归通过，补充评分器试评分身份后相关 2 项重跑通过。Judge/合同/摘要相关检查通过；扩展 Mongo 准备测试最初发现旧三集合断言和命令未同步，修复后 4 项通过。新增多评分器执行测试确认被测模型只调用一次、两个 Judge 各调用一次、各自证据文件及阈值独立、参考答案不进入被测请求。CSV 和摘要身份/费用测试通过。
