# SPEC-023：案例列表拖动与快速选择

状态：Implemented / 已实施
确认记录：2026-10-26 用户回复“继续实施”，批准本方案。
日期：2026-10-26（北京时间）
范围：首页“全部案例”、模块案例列表及新建评测的案例选择区；不改存储或模型执行。

## 目标与当前行为

当前列表支持逐项复选框及勾选全部筛选结果，但不支持选择连续区间或拖动选取部分案例。选择会保留被筛选隐藏的项目，行点击会进入详情。已阅读内网 roadmap、SPEC-005/006、app.ts 中 renderCases、caseRow 和新建评测选择器。

## 交互方案

- Shift + 点击复选框，按当前可见排序从最近一次手动勾选项到目标项选择连续区间；区间采用目标动作：勾选或取消。区间外与隐藏项保持原选择。
- 在复选框列按下鼠标并纵向拖动，经过的连续行按起点动作统一选中或取消；返回已经经过的行不反复翻转。鼠标释放结束，拖到可滚动容器边缘时自动滚动。
- 拖动只从选择列开始，避免与案例名称、按钮和文本选取冲突。拖动达到阈值才进入选择手势；完成后抑制对应 click，不能误入详情或触发运行/删除。
- 工具栏提供“全选筛选结果”“反选筛选结果”“清空选择”，以及简短帮助“拖动复选框列或 Shift 连选”。原表头全选继续可用。
- 批量条持续显示已选总数及隐藏选择数；所有批量操作仍按完整选择集合执行。筛选不自动清除隐藏项；反选仅影响当前可见结果。
- 新建评测的案例选择区复用区间选择交互，维护它已有的模块包含/案例排除语义，不能更改最终提交范围。
- 键盘继续支持 Tab/Space，Shift + Space 可作区间选择；触屏保留普通勾选及快速选择按钮，不抢占纵向滚动。

## 状态与边界

- 以稳定 SavedCase.id 存储选择，区间按当前 visible 顺序计算，不按业务名称或旧 DOM 下标。
- 搜索、筛选、模块、排序或数据刷新导致可见集合变化时结束拖动并重置区间锚点；保留有效选择，删除的案例移出集合。
- Pointer capture、pointercancel、窗口失焦或页面离开均终止手势和滚动定时器；Esc 停止手势并保留已作选择，不触发批量操作。
- 手势过程中局部更新复选框与选择计数，避免每经过一行就替换全部 DOM 导致丢失 capture、焦点或滚动位置。
- 空列表禁用批量选择；隐藏项不被拖动选中；长列表和横向滚动不影响选择列命中。

## 兼容与异常

无服务端接口、依赖或数据迁移。已有单项勾选、表头全选、名称链接、行导航、批量复制/移动/删除/评测、筛选记忆继续生效。请求失败仍保留选择，沿用现有隐藏选择提示。
