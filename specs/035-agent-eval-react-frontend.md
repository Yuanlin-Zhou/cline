## 1. 目标与范围

用 React + TypeScript、Vite 和 TanStack Query 重建当前完整 Web 前端，收敛页面状态、请求生命周期与组件复用。保留现有信息结构、中文文案、已确认偏好和功能，不借框架迁移重做产品交互。

范围包括案例/模块管理、导入、案例详情/编辑/复制、创建评测、批次列表/详情、Attempt/重试、报告/产物/会话、验证脚本管理及试验证、Judge 配置/试评分和全局配置。不能用 React 外壳长期包住原有 DOM 大入口宣称完成迁移。

本期不实施服务端任务系统、认证、数据库或评测语义变更，不引入 Next.js/SSR。

## 2. 当前行为与保留依据

已阅读应用 AGENTS.md、内网 roadmap、SPEC-015/025/026/031/032/033，以及旧客户端 app.ts 和分离编辑器列表、API、构建与 smoke 脚本。

- 约 2,900 行入口混合 hash 路由、DOM 构建、API、轮询、表单和弹窗，并已有多个可复用编辑器。
- 列表通过摘要加载；当前案例/运行项详情按需获取；大批次使用变化游标和有限轮询。
- 交互已支持拖选/Shift/筛选全选、跨案例复制配置、保存冲突提示、历史消息导入和原始 Bad case 展示。
- 所有这些行为属于迁移合同，不能通过删功能缩小迁移量。

## 3. 技术选择

| 能力 | 选择 | 原因 |
|---|---|---|
| UI | React + TypeScript | 与仓库已有生态兼容，便于多人维护状态和组件 |
| 构建 | Vite + React 插件 | 将资源构建与服务启动分开，提供开发 HMR |
| 服务端状态 | TanStack Query | 统一请求、缓存、失效、取消与轮询 |
| 路由 | React Router 的 hash 路由 | 保持现有书签/链接，无需改变服务端回退策略 |
| UI 基础 | 本地组件 + Radix Dialog/Tabs 等必要可访问性原语 | 复用现有 CSS 和视觉规则，避免整套换肤 |
| 表单 | React 受控组件、业务级 hooks、既有合同解析 | 明确草稿/保存边界，不额外叠加全局表单状态框架 |
| 浏览器验收 | Playwright | 验证实际操作、视口和截图 |

版本在安装时选择相互兼容的稳定发布版并由 Bun lockfile 固定；使用 Bun 安装/运行，不切换包管理器。业务状态优先放本地 hook/context，不引入 Redux 等全局状态库。

## 4. 前端组织

```text
apps/agent-eval/web/
  index.html
  vite.config.ts
  tsconfig.json
  src/
    app/                     # 启动、路由、providers 和页面壳
    api/                     # HTTP 客户端、错误类型、query keys
    components/              # 表单、状态、弹窗、列表等通用组件
    features/
      catalog/               # 模块/案例列表及操作
      case-editor/           # 输入、工具历史、回放和规则配置
      imports/               # 文件/批量对话预览与确认
      runs/                  # 批次、新建、进度和重试
      results/               # Attempt、会话、产物与报告
      verifiers/             # 验证脚本管理与试验证
      judging/               # 配置与试评分
      settings/
    hooks/
    styles/
  tests/
```

DOM 编辑器按功能改成真正的 React 组件/hook；纯解析、格式化与业务计算可保留并复用。禁止把服务端文件系统、数据库或 SDK runtime 打入浏览器。

## 5. 数据、缓存与交互规则

- API 路径和响应合同保持 SPEC-034 约定；使用统一的带 AbortSignal HTTP 客户端，取消过期请求，防止路由切换后回填旧页面。
- Query key 包含模块/案例/批次/运行项/Attempt 等身份；mutation 成功后只失效相关数据，不重新下载所有案例正文。
- 摘要、详情、证据和历史分开查询；保留 SPEC-026 的懒加载与增量游标。选择状态只保存 ID。
- 运行中轮询需要遵循页面可见性、任务终态和组件卸载；同一个资源不启动多份轮询。交互以既有间隔为起点，不引入 SSE/WebSocket。
- 创建任务、重试、删除、导入和付费 Judge 操作不做自动 mutation 重试；使用原有幂等协议，等待期间禁用重复提交。
- 编辑草稿与查询缓存分离。自动刷新不能覆盖未保存字段；切换页面/关闭弹窗时保留现有未保存提示。
- 敏感/大对象不写浏览器持久缓存。复用现有明示的 header/凭据引用规则，不额外新增脱敏策略。
- 表单校验复用共享纯函数；内网 Java/Python 导入合同不受 UI 改写影响。

## 6. 构建和启动

- build:web 生成独立的版本化静态产物；生产启动直接服务这些资源，不再在服务启动阶段 Bun.build 前端。
- 开发通过 Vite HMR 和同源 API 代理访问后端；保持现有 localhost/Origin 校验，不为代理放宽团队访问限制。
- 原有一条 Web 启动命令保持可用：开发/本地启动可在资源缺失时先运行构建，正式 start:web 对缺失资源明确报错，不静默启动半成品。
- 构建输出和缓存位于 ignore 的目录；发布包包含静态资源、后端/Worker 入口及所需配置。验证 Windows 与 Linux 的路径处理。
- 现有 hash 深链接、下载、刷新、浏览器返回/前进可用；兼容旧路由编码，必要时显式映射，不静默失效。

## 7. 迁移批次

1. 在实现改动前记录桌面/窄屏当前主要页面和接口行为；建立不调用真实模型的确定性验收数据。
2. 搭建 React/Vite、页面壳、路由、QueryClient 与基础组件；以设置页和案例列表建立请求/表单规范。
3. 迁移案例编辑/复制、历史/批量导入、Bad case、回放配置、断言与规则编辑、Judge 配置。
4. 迁移新建评测、批次列表/详情、进度、Attempt、取消/重试、结果检查器、报告与文件/会话查看。
5. 迁移验证器管理/试验证和 Judge 试评分，补齐边界交互。
6. 清除旧 DOM app.ts 与旧编辑器业务入口，整理样式、构建、发布和文档；完成整体验收。

中间可按页面过渡，但最终交付覆盖全部现有页面；保留纯函数不等于保留旧 DOM 应用。每一批都能单独验证，不能以所有页面迁完后才发现合同偏差的方式推进。

### 实际 UI 复核

使用 Chromium，桌面 1440×900、窄屏 390×844。逐页打开并查看截图，复核案例列表/编辑、设置、两种导入入口、脚本管理、批次列表/向导/详情、结构化报告及执行检查器；另外检查长名称/长 Bad case、空脚本库、无文本输出和网络错误重试。主要页面无整体横向溢出，表格和页签在各自容器内滚动；控制台无新异常。

发现并修复：

- 模块操作按钮过高、窄屏名称挤占计数：收紧操作间距，以独立网格列布局名称和计数。
- 长名称/窄屏撑高列表和详情标题：表格固定列宽、案例名称最多三行；详情标题最多三行，完整名称仍可在名称输入框编辑，面包屑省略。
- 回放方式卡片不换行导致溢出：允许卡片正文换行；保留按钮的可访问名称及选中状态。
- 拖选过程中选择工具栏改变行坐标、释放点击重复切换：拖动时冻结工具栏布局，识别并抑制释放后的多余点击；Shift 锚点使用稳定案例 UUID。
- 原生 details 标记与旧 CSS 标记重复：隐藏原生标记，保留现有视觉标记。
- 非法 JSON 因对象重新创建而被覆盖、跨页签草稿丢失：按规范化值同步编辑器并保留页签组件，保存前统一校验。
- 终态仍展示执行阶段文案：只在排队/运行时显示阶段。
