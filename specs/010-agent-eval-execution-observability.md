# SPEC-010：评测执行状态与会话记录

- 状态：**Implemented / 已实施**
- 日期：2026-10-09
- 确认记录：用户在审阅“执行状态＋会话记录、保留异常输出、合并高频写入”的具体建议后回复“继续实施”。本文件补齐该已批准方案，不重复请求确认。
- 关联：`docs/agent-eval-intranet-roadmap.md`，历史 SPEC-001，以及根目录 SPEC-008、SPEC-009。

## 1. 目标与范围

运行页面能够分别回答当前阶段、收到过什么活动、最终结果。单案例调试与批次详情采用相同展示；最终回复仍作为结果证据，实时文本预览默认折叠，完整会话有独立入口、刷新与下载功能。仅修改 agent-eval，不修改 SDK、评分合同、行为证据能力或 MongoDB/SQLite 的职责划分。

## 2. 当前行为

runner 仅转发 text content_start，worker 输出文本 JSONL，queue 每片段写入完整 RunItem。工具事件只归档为诊断；SDK 独立 session 目录包含 messages 文件。前端每秒轮询完整批次，网络异常静默重试；文本框无轮次分隔，验证阶段文本自然不变；单案例执行错误隐藏部分输出。

## 3. 方案与接口

- RunItem 增加可选 sessionId、lastActivityAt、activity（类型、时间、迭代、工具名）及最近活动列表。收到 SDK 迭代/文本/工具/结束等事件时记录活动，不以心跳伪造模型进展。工具事件标注“请求/收到结果”，不证明工具实际执行。
- worker 新增 activity 消息，沿用 SDK 已有事件；隔离执行把活动转发给 queue。CLINE_SESSION_DATA_DIR 固定到本次运行目录，避免外部配置导致会话串用。
- queue 将文本与活动写入合并为每 250ms 至多一次；开始、阶段变化、会话绑定和终态立即落库，结束/取消/异常强制刷入。保留原 text 字段和上限，兼容既有导出。
- `GET /api/runs/:run/items/:item/conversation?offset=0&limit=50`：后端适配本次 session/sessions/:sessionId/:sessionId.messages.json，返回规范化消息（稳定 ID、索引、角色、内容块、时间）、总数、后续分页、读取状态及提示。支持下载规范化 JSON；不返回 system_prompt 或存储路径。历史缺失/写入中/格式异常/超过读取上限均有明确提示，不能报“没有对话”。
- 文件读取限定到当前运行，拒绝路径穿越与符号链接越界，最大文件 32MiB、每页最多100条。沿用现有执行输出的凭据替换范围，不扩展 SDK 日志脱敏。文件格式适配失败不改变评测结果；保留最终回复和旧文本作为回退。
- 前端状态卡显示阶段、耗时、最近活动、活动摘要、同步状态；无新活动只说明等待，不自动断言卡死，也不新增静默超时。会话按消息及内容块展示文本、工具请求与结果；实时预览明确标注片段，不能冒充完整记录。
- 保留文件产物、输入快照、工具诊断；结果默认优先展示判分。错误、取消、中断时保留部分输出和已持久化会话。轮询错误显式显示，恢复后清除；使用请求超时防止一次挂起阻断后续刷新。
- 先保留轮询，只有当前选中详情读取会话，分页按需加载；本次不增加 SSE 或拆分批次存储/接口。

## 4. 兼容性与异常

新字段均可选；旧记录没有实时活动，显示“未记录活动”。从最终 result.sessionId 回退定位会话；缺失文件仍能看结果/旧输出。SDK 会话文件是其保存的上下文记录，可能包含压缩后上下文，界面不得保证全量永久历史。刷新失败保留已展示内容，不阻断取消按钮。取消请求后的运行项未终结时继续同步到项终态。

## 5. 验收标准

1. 慢模型没有文本时显示执行中与正常同步；工具活动改变摘要；验证阶段明确显示验证中。
2. 单案例与批次详情可查看分页会话、展开工具块、下载记录；刷新页面与服务重启后已落盘记录仍可读。
3. 网络故障显示同步失败且可恢复，执行错误/取消保留文本。
4. 会话缺失、写入中、非法格式、超限、跨运行访问与符号链接越界处理明确。
5. 文本突发只触发有限写入，终态最后片段不丢；历史数据兼容。
6. 使用本地模拟模型验证真实 worker 到 Web 的状态、会话链路；类型检查、相关测试和 Web smoke 通过。

## 6. 实施步骤

活动事件与合并写入 → 会话读取接口与异常测试 → 两处详情共享状态/会话展示 → 本地模拟模型与浏览器验收 → 更新文档和验证记录。

## 7. 实施与验证记录

实施日期：2026-10-09，分支 `work`，基于 `18d3fc4`。

- runner/worker 转发精简活动元数据；隔离执行固定会话目录并绑定实时 sessionId。最近30项活动保留在现有 RunItem，连续同类活动合并，不记录推理正文或工具参数到进度元数据。
- queue 文本/活动每250ms合并写入；会话、工作区、阶段与终态立即刷入，异常与取消保留部分文本。未更改评分、SDK 或案例存储合同，无需 MongoDB 集合迁移。
- 会话接口支持50条默认分页、100条上限、JSON下载、旧 result.sessionId 回退、缺失/写入中/格式不支持/超限等状态，并检查所有权与文件范围。
- 单案例与批次复用详情组件：运行状态、同步状态、折叠预览、最终回复、会话记录、工具诊断。取消后继续同步至运行项结束；已结束项不会因其他项轮询而反复重建结果。会话同步失败或暂时不可读取时保留已展示内容。
- 会话默认跟随最新保存的50条消息；切换最早消息/下一页暂停跟随，避免运行中被新消息打断查阅，点击最新消息恢复。
- README 与 STARTUP 增补入口、记录保存时机及故障排查。
