## 1. 目标与范围

根据用户截图优化“自定义模型请求头”编辑区，让每条请求头的名称、值来源、值和删除操作形成清晰的一组，减少拥挤和重复占位提示。沿用现有页面的字体、颜色、圆角、按钮和边框风格。

共用组件的设置页、批次配置、案例默认请求头及案例覆盖区同步生效。不改 SDK、不新增脱敏、不更改请求头配置和模型调用逻辑。

已阅读开发约定、内网 roadmap、spec 001 与现有组件/CSS。按约定先提交 Draft，明确确认后修改实现代码。

## 2. 当前问题

- headerEditor 使用通用 `.form-row`，该样式固定两列。每条请求头有四个控件，因此自动拆成两行，删除按钮占据半行宽度。
- 请求头条目之间没有独立间距与边界，上一条的值输入框与下一条的名称框连在一起，难以区分。
- 固定占位符重复显示 x-session-id / {{sessionId}}，缺少可见字段标签。
- 说明文字较长，视觉权重接近表单；添加按钮位于列表最下方，没有清晰工具栏。
- 当前配置页面自身可能是多列布局，只依据浏览器宽度决定编辑器列数会导致窄容器溢出。

## 3. 设计方案

### 区域结构

1. 顶部工具栏：左侧标题，右侧“＋ 添加请求头”。窄容器下可自然换行。
2. 简短说明：“为模型请求添加固定值或环境变量引用。”
3. 有条目时，每条显示为独立浅色卡片：轻边框、圆角、统一内边距，卡片之间保留 12px 间距。
4. 无条目时显示轻量虚线空状态：“暂无自定义请求头”，提示点击添加；不自动填入示例值。
5. 底部辅助说明集中解释环境变量和三个模板，用等宽 code 展示模板，不做点击填入操作。

### 每条请求头

宽容器（约 680px 及以上）采用四列：

```text
请求头名称              值来源           请求头值 / 环境变量名       删除
[x-session-id       ]  [固定值  ▾]      [{{sessionId}}         ]    [×]
```

- 名称和值使用可读的等宽字体；来源列较窄，值列获得更多空间。
- 每个字段有可见标签，与控件通过 label/for 关联；来源切换时更新值字段标签和占位提示。
- 删除改为紧凑图标按钮，带“删除此请求头”的可访问名称和悬停提示，悬停使用现有危险色。触屏点击区域至少 44px。
- 中等容器：名称与删除在首行，来源和值在次行。
- 更窄容器（约 420px 以下）：三个字段纵向排列，删除留在卡片顶部右侧。输入框始终可缩小，不产生横向滚动。
- 使用组件专用类名与容器查询，不修改通用 `.form-row`，避免影响其他表单。

### 交互细节

- 点击添加后聚焦新条目的名称输入框；移除最后一个条目恢复空状态。
- 来源切换保留用户已填值，数据读取与校验沿用现有函数。
- 保留键盘焦点样式、按钮 type=button 和现有字段识别 data 属性。

## 4. 接口与兼容性

- headers、headersEnv、模板和大小写覆盖规则不变，不引入配置迁移或新依赖。
- headerEditor / readHeaderEditor 的调用接口保持不变。
- 原控件 aria 属性和 data-header-* 选择器继续可用，既有配置保存与 worker 传递测试继续运行。
- 样式仅作用于请求头编辑组件；现有设置页、批次和案例表单保留各自布局。

## 5. 异常处理

非法名称、重复头、缺失环境变量和凭据字面值继续由现有解析逻辑处理。本次不增加新的错误规则。

字段内容较长时保持输入框自身滚动，不撑开卡片。辅助说明和模板可换行，窄容器不截断关键说明。
