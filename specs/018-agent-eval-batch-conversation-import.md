# SPEC-018：批量会话 JSON 转单轮函数调用案例

- 状态：**Implemented / 已实施**
- 确认记录：2026-10-21 用户回复“继续实施”，批准修订后的完整保留历史及自动续接规则。
- 日期：2026-10-21（北京时间）
- 来源：用户要求批量选择逐个 JSON 会话文件，批量生成单轮函数调用案例。
- 方案修订：用户要求取消“向前寻找最后一条用户消息并截断”的默认规则；助手/工具结尾时自动追加用户消息“继续”。用户已确认：末尾已经是普通用户消息时，直接作为本轮输入，不再追加“继续”。
- 关联：SPEC-014、SPEC-017；沿用 work 分支及现有 Python 验证器、原生会话转换能力。不修改 SDK。

## 1. 目标及现状

案例列表已有 JSON/JSONL 案例集导入，但只读取一个文件，要求内容本身为案例集或案例数组，不能将 messages 日志直接变为案例。单案例页面已有粘贴会话、选择回放位置与原生工具链转换，复用其解析合同而不另做宽松解析。

目标：一次多选若干 .json 会话文件，一份文件生成一个 replayMode=function-call 案例，批量校验预览后导入指定模块，不必逐个打开编辑器粘贴。导入仅创建/更新案例，不请求模型、不执行历史工具。

## 2. 用户入口与流程

在“案例集 → 导入案例”增加两个清楚的来源选项：原来的“案例集 JSON/JSONL”和新的“历史对话 JSON（批量生成案例）”。从某模块进入时自动带入该目标模块。原导入方式保持不变。

新方式分三步：

1. **选文件和公共设置**：目标模块、多文件选择、本轮输入生成方式、本轮可用工具（默认现有六工具）、toolChoice（默认 auto）。模型连接沿用当前运行配置，预览给出非 OpenAI-compatible/缺少 baseUrl 等执行配置提醒，不凭历史日志推断连接和凭据。
2. **逐文件校验与预览**：列表展示文件名、可编辑案例 ID、本轮输入摘要、原始记录保留数量、是否自动追加用户消息、校验结果及同名状态。顶部显示可导入/错误/同名数量。选中一行在侧区或弹窗查看已有的中文对话卡片、调用链和转换说明，不同时展开所有文件的完整 JSON。
3. **确认导入**：显示目标模块、实际选入文件和同名策略，提交后显示新建/更新/跳过数量并返回目标模块。导入期间禁用重复提交；错误保留文件和设置，不回到空表单。

支持移除文件、更改案例 ID、逐文件修改追加的本轮输入。文件内容/公共设置/本轮输入/案例 ID 改变后使旧预览失效，重新校验后才可确认。切换原导入方式不触发任何写入。

## 3. 一份记录如何变为案例

### 3.1 支持格式

复用 readHistoryDocument/convertHistoryDocument：Cline 原生 .messages.json、标准 messages 对象或直接数组、type/data 包装、messgaes 别名、reasoning_content 和已有 thinking 内容块处理。

文件按 UTF-8（允许 BOM）读取，非法编码明确要求另存为 UTF-8，不按 GBK 猜测或替换乱码。所有文件通过浏览器显式选择，不接受服务端任意文件路径，不递归读取本机目录。

### 3.2 完整保留历史与自动续接

取消向前寻找“最后一条纯文本用户消息”及截断后续消息的规则。导入的原有对话保持完整顺序，不能丢弃已经发生的助手回复或工具轨迹。保留现有明确的思考/多模态转换规则，不承诺原请求逐字节回放。

对于记录的实际末尾：

| 实际末条消息 | 批量导入处理 |
| --- | --- |
| assistant 普通回复 | 整份原记录作为历史，自动追加 role=user、content="继续" 作为本轮输入 |
| role=tool 或 Cline user/tool_result，且所有调用均有结果 | 整份原记录作为历史，自动追加 role=user、content="继续" 作为本轮输入 |
| assistant.tool_calls / Cline tool_use，仍缺少工具结果 | 先标记为待补全，不能直接在未闭合工具链后追加 user 并称可执行；提示补齐对应工具结果，不执行工具、不伪造成功/空结果 |
| 纯文本 user 已位于文件末尾 | 仅将实际末条作为本轮输入，其前全部消息作为历史；不再追加“继续”，不向前寻找其他 user，也不丢弃中间内容 |
| 只有工具结果、缺少前文调用的压缩片段 | 按已有校验报错，不伪造调用 |

新增用户消息的默认文案为“继续”，可以在公共设置中统一修改，也可逐文件修改，最终内容必须非空。界面说明“保留完整历史，并根据对话末尾追加本轮用户输入”，预览中把自动生成的本轮消息单独标注，不与原始消息混为一谈。

“没有纯文本用户问题”不再单独作为失败条件：只要导入的历史非空、协议和工具链完整，可按上述规则追加“继续”。明确选择其他本轮内容时，同样保留原历史，不自动回到旧的截断模式。

例如：原记录为 user → assistant.tool_calls → tool → assistant，生成的实际请求为 user → assistant.tool_calls → tool → assistant → user("继续")；原 assistant 和 tool 都保留。最后一条 tool_use 尚未完成时，缺少工具结果属于协议问题，不能仅靠补一句“继续”解决。

reasoning_content 纯空白自动省略；实际思考默认阻止应用。提供明确公共勾选“仅导入文本和工具轨迹，不发送思考内容”，并逐文件显示省略提示。图片/媒体、断裂调用链、未知协议字段等按现有规则报错。

### 3.3 案例名称、参数及判定

- 默认案例 ID 为去掉 .json 扩展名后的文件名；显示并允许编辑。批内同名默认给出 -2/-3 的可见编号，最终选入的案例 ID 必须非空且唯一；手动编辑造成重名时定位到行，不偷偷覆盖。
- 案例 description 标注来源文件名，沿用已有字段，不额外复制原始文件；规范化历史保留原有助手回复和工具轨迹。functionCall.history/historySource 使用已有合同；旧普通 history 为空。
- 本轮可用工具和 toolChoice 使用公共选择，不从历史 assistant 的工具调用自动推断，因为那些不是本轮待验证响应。导入系统提示词时沿用现有优先级。
- 可选给整批绑定一个已有 Python 结果验证器（明确应用于所有选入案例，工具不同可分批导入）；默认不绑定。未绑定时明确提示“仅创建案例，尚未配置自动判定”，不把原历史回答当作标准答案自动生成规则。
- 模型配置为打开导入页时取得、在预览中使用的运行配置快照，确认时显式提交并做 schema 校验，不因操作过程中全局设置变化悄悄换模型。沿用已有验证脚本 ID 引用和执行时源码快照机制。

## 4. 接口与事务

新增批量会话导入 preview/commit API，建议 /api/import/conversations/preview 和 /api/import/conversations。输入为目标模块、显式选入的文件项（filename、UTF-8 content、caseId、可选本轮续接文案）、公共设置（续接规则/统一 prompt、工具、toolChoice、思考处理、可选 Python verifierId）、默认配置快照和同名策略。

客户端可做快速解析，但服务端必须重新逐文件执行共享转换与 parseEvalSuite；不能仅信任浏览器的校验成功标记。preview 返回逐文件错误、规范化草稿、转换摘要和目标模块同名状态，错误信息带文件名及具体消息/参数路径。commit 对实际选入内容重新转换和校验，校验通过后一次调用既有 catalog.importCases。

默认同名处理沿用“跳过，保留现有案例”；可显式选择“创建新版本，覆盖案例内容”。数据库中的同名以提交时状态为准，最终结果分别统计，不把同批重复 ID 当作数据库覆盖策略处理。

存在选入文件错误时整批不写。用户可以明确移除/排除错误文件后，只导入剩余通过校验的部分；不能自动忽略失败项。SQLite 和 MongoDB 沿用既有事务，数据库写入失败整批回滚，不出现前几个文件已写、后几个失败的情况。模块不存在/已归档时拒绝导入。

提交前检查所选 Python 验证器存在且运行类型正确，不执行脚本，也不自动上传或安装依赖。无数据库新字段或集合迁移，不需为批量入口额外执行 mongo:prepare；前提是部署已支持 SPEC-017 的 history/historySource。

## 5. 限制与异常

- 首期仅支持多选独立 .json 文件，不含 ZIP、文件夹、JSONL 多会话拆分或一次从一个文件拆多个案例。
- 单文件至多 1 MiB/500 条原始消息，规范化历史保持既有限额；单批至多 100 文件，原始内容合计和提交请求分别至多 20 MiB。前后端都检查，限制不通过时不读库写库。
- JSON 无效、编码错误、记录被压缩而断链、续接文案为空、缺少工具结果、无效参数或思考未确认均可定位到具体文件；失败与取消保留原案例库。
- 无网络时文件预览可保留，但最终同名检查/提交必须明确失败，不显示导入成功。响应不明时先刷新检查，避免把重试解释为一定没有提交。
- 原会话 sessionId 仅作来源展示，不覆盖后续运行生成的 sessionId/requestId。完整原始文件仅用于本次预览与提交转换，不单独持久化。
