# SPEC-021：当前评测内重试未通过案例

状态：Implemented / 已实施
确认记录：2026-10-26 用户回复“继续实施”，批准本方案。
日期：2026-10-26（北京时间）
范围：agent-eval Web、运行存储、队列、统计与导出；不修改 SDK。

## 目标与当前行为

用户要求未通过案例在当前评测内重试，并显示重试次数。当前 `rerunFailed` 向 `POST /api/runs` 传入 parentRunId，创建子批次；RunItem 只有 round，没有重试记录。已阅读内网 roadmap、SPEC-005/010/013/015/019，以及 store、queue、server、types、repeat-report 和前端实现。

## 交互方案

- 批次列表与批次详情的“重跑未通过案例”改为“重试未通过案例”。确认区显示待重试数量；提交成功留在原批次，不创建新评测。
- 范围为各案例各轮的最新执行中 failed、error、inconclusive、cancelled 的项。已通过项不重试；一项在多轮失败则分别重试，不合并轮次。
- 只在批次已结束时允许操作，运行中不可追加。沿用原并发数；支持在结果详情重试单个未通过项。
- 结果列表每个“案例 × 轮次”只显示一行最新执行，标记“重试 1 次 / 2 次…”。首次执行为 0 次；批次摘要显示累计重试执行次数。
- 详情提供“首次执行 / 第 1 次重试 / …”切换，分别查看状态、输出、错误、session_id、日志和产物；旧结果完整保留。
- “重复评测本批次”仍用于新建重复实验，不与故障重试混用。

### 2026-10-26 已确认的补充范围

用户在实施中明确调整：可以按失败原因选择案例，例如仅重试全部“无法判定”或全部“断言失败”。此指令直接授权本补充范围，无需再次确认。

- 重试弹窗提供“断言失败 / 执行错误 / 无法判定 / 已取消”复选项，显示各类当前最新执行数量；支持单类或多类组合，默认勾选有可重试项的类别。
- 提供“全部未通过”快捷选择；实时显示本次执行数量，空选择或所选类别无可执行项时禁用提交。单案例入口仍只作用于该项。
- 重试接口支持可选 statuses 数组；仅接受以上状态，服务器重新核验最新项、所选项和原因范围。原因筛选同样纳入 requestId 幂等参数；不因预览失效自动扩大范围。
- 案例多轮执行按“案例 × 轮次”的最新状态筛选，确认时同时说明涉及案例数与执行次数。
- 验收新增：仅无法判定、仅断言失败、多类组合、无匹配、已恢复通过、陈旧选择和重发幂等。

## 数据与接口

- RunItem 增加可选 rootItemId（首次执行 ID）、attempt（首次 0）、previousItemId；沿用 runId 和 round。缺字段的旧项按首次执行处理。
- 重试创建新 RunItem、新工作目录和新会话，复制首次提交的案例及验证脚本快照；不读取案例库的新配置，也不接续旧对话。若要更改配置，用户另建评测。
- 复制工作区模式按原 fixture 重新准备；直接执行模式仍使用实际目录，确认区提示会在该目录当前内容上再次执行，不承诺恢复首次文件状态。
- 增加 `POST /api/runs/:id/retry`，body 为 `{ requestId, expectedRetryRevision, itemIds? }`。省略 itemIds 表示全部可重试的最新项；指定项必须属于此批次且仍是最新未通过项。
- Run 增加 retryRevision，旧值默认 0。SQLite immediate 事务重新校验批次状态、revision、选择范围，原子创建新项、登记 requestId 和恢复 queued 状态，清除当前 endedAt 后唤醒队列。
- 同一 requestId、相同参数重复提交返回原响应；同键不同参数返回 409。批次 revision 或选择已过期返回 409，禁止自动扩大范围或重复排队。此幂等记录与创建项在同一事务保存。
- 同时保留批次首次创建时间及每次执行的起止时间；重启后新排队/运行项沿用现有中断恢复机制，不能覆盖已完成尝试。

## 统计与兼容性

- 明确区分全部尝试和最新执行：状态数量、通过率、模块摘要、案例最近结果和多轮比较以每个 rootItemId 的最新执行为准，重试不会增加案例数或 repeatCount。
- Token、费用、累计执行耗时统计全部尝试；未知费用仍标为未提供。附带首次结果与重试历史，避免重试后掩盖首次失败。
- 多轮报告默认比较各轮最新结果，并标注“含重试结果”；提供查看首次结果，重试不当作新增实验轮次。
- JSON 保留全部尝试并增加有效项标记/重试摘要；CSV 增加 root_item_id、attempt、previous_item_id、is_latest；Markdown 标明首次/最新结果与累计重试。
- 旧批次无需破坏性迁移；没有重试的现有统计和链接保持有效。旧 parentRunId API 保留兼容，但新版重试按钮使用新接口。所有旧产物按原 itemId 访问。

## 异常处理与验收

1. 失败后在同一 runId 重试成功，列表仍只有原批次，次数递增且刷新后保留；原失败详情可查看。
2. 多轮混合结果只重试指定失败轮次；已通过项、旧尝试和其他批次项不能被错误提交。
3. 重复点击、网络重发、两个页面并发、过期 revision 不会重复执行；事务失败无部分写入。
4. 取消、重启中断、案例被修改或删除后仍能按冻结快照追溯执行，验证脚本不依赖在线案例库。
5. UI、API、导出、历史、成本和多轮报告使用上述统计口径，覆盖旧数据回归。
6. 添加有意义的 Store/API/队列与统计测试，运行类型检查、Web 冒烟和浏览器交互验证。
