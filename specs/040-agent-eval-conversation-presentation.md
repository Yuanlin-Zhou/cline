# SPEC-040：会话历史展示修复

## 目标与当前行为

修复结果工作台“会话与工具”的展示。当前 inspector.tsx 的 Conversation 将所有 block.text 直接交给 JsonView，文本、thinking 和工具输入输出缺乏区分，块间紧贴，长内容占满页面。已阅读根目录及应用 AGENTS、内网 roadmap、SPEC-025/039、会话展示及证据转换代码。

## 方案

- 延续 Ant Design。消息卡片显示序号、角色；正文、工具调用、工具结果使用明确标题和统一间距。下载操作与首条消息分开。
- 普通文字按段落保留换行；代码/JSON 使用等宽内容容器。长内容默认限制高度，可展开/收起和局部滚动，短内容不预留空白。
- 已保存的 thinking 块标注为“思考记录”，默认折叠；不新增采集、不推断缺失内容。未知类型保留原始内容入口。
- 工具参数及返回按块分别展示；仅当存在真实关联 ID 时显示对应关系，不能仅凭名称猜测配对。保留原始内容查看及完整会话下载。
- user_input 等运行时包装只在明确识别格式时提供正文视图，同时保留原始内容，不对任意文本做通用标签删除。
- 空会话显示 Empty，计数为 0；换执行记录时重置分页。保留加载、错误/重试与执行中刷新。

## 接口、兼容与异常

优先复用会话接口已有块类型和工具标识；如需补充展示字段，仅增可选字段，不更改原始会话、证据或评分材料。坏 JSON/未知块显示原始文本，不导致页面崩溃；保持原有上下文可能被压缩的说明。

## 验收与步骤

确认后实现分块展示及必要字段适配；覆盖纯文本、工具请求/返回、多块、长 JSON、未知块、空/错误/重试、跨记录分页。桌面真实浏览器检查并亲自查看截图；运行类型检查、构建及相关浏览器回归。只要求桌面端，不做手机适配。完成后记录结果并标记 Implemented。
