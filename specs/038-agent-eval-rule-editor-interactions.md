## 1. 目标与范围

修复案例新增/编辑页判定规则添加后无法移除区域、LLM 评分入口无可见反馈的问题。覆盖最终回复、文件产物、Python 验证器、LLM 评分及保存重开；不改变判分引擎与数据合同。组件外观按 SPEC-039 使用 Ant Design。

已阅读根目录与应用 AGENTS.md、内网 roadmap、SPEC-025/035/036，以及 rules.tsx、judging/editor.tsx、case-editor/page.tsx 和公共 UI 组件。

## 2. 当前行为与原因

- 最终回复入口仅将 replyOpen 设置为 true，字段和整个区域没有删除入口；activeReplyFields 还合并了已有非空数据，单改展开状态无法移除内容。
- 文件/Python 共用任务验收区域。已有单条规则“移除检查”，但 filesOpen 无关闭路径，删完仍留下区域；顶部入口只是打开添加器，不直接生成规则。
- judgeOpen 初始为 true，LLM 入口再次设置 true，不启用评分也不定位表单，表现为点击无反应。
- JudgeEditor 支持关闭评分并保留配置；须保留这个已有行为。

## 3. 交互与数据方案

1. 顶部入口统一为添加或定位配置：首次点击打开对应区域，已有区域则滚动到区域并聚焦首个可编辑控件，不重复添加规则。显示“已配置/未配置”等状态，键盘可操作。
2. 最终回复的包含、不包含、正则字段分别提供“移除检查”；同时清理该字段的界面状态和 assertions 对应数据。最后一个字段删除后隐藏空区域。保留 finishReason 等其他 assertions。
3. 最终回复区域提供“移除最终回复检查”；仅清理三个文本断言字段。含已填内容时使用 Popconfirm 确认，空区域直接移除。
4. 任务验收区域保留显式“添加检查”和单条删除，增加“移除全部验收检查”。有规则时确认清除 grading.rules，空区域直接关闭。删除最后一条后隐藏区域。文件与 Python 共用此区域，整体移除明确提示会删除所有验收规则，不能伪装为只删除文件检查。
5. LLM 入口首次点击启用评分并展开、定位表单；有停用配置时恢复原配置，有启用配置时仅定位。未配置区域不默认显示空评分表单。停用保留已填配置，并可从入口重新启用；另提供“移除评分配置”，有内容时确认并清除 llmJudge。移除不影响确定性检查。
6. 保留现有文件检查需要完整任务的限制与切换行为、规则 JSON 编辑和历史试验证/试评分入口。JSON 修改与可视化区域同步，不残留已经删除的规则或状态。
7. 删除属于本地草稿修改，统一通过现有保存操作持久化；纳入未保存离开提示。刷新已保存案例不能恢复已删除配置。

## 4. 兼容性与异常处理

不增加 API、数据库字段或版本迁移；原案例按现有配置初始化区域。启用 Judge 后仍执行原有参考答案、模型、评分目标校验，点击入口不发起模型调用。保存失败/版本冲突保留草稿并展示原有错误，取消删除不修改任何数据。保持试评分任务身份和生命周期，不因折叠/移除表单误发新请求。
