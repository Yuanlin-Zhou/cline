# SPEC-022：评测结果摘要精简

状态：Implemented / 已实施
确认记录：2026-10-26 用户回复“继续实施”，批准本方案。
日期：2026-10-26（北京时间）
范围：agent-eval 批次列表、详情、多轮报告和案例结果展示；不改变判分引擎。

## 目标与当前行为

依据用户截图，结果区域同时平铺旧版文本统计、按案例/规则 hash 的任务通过率、全部成功比例、覆盖率、关键约束和多个零值指标，且重复说明计算方式。`gradingMetrics` 被批次详情和多轮报告复用，批次顶部又重复展示状态。已阅读内网 roadmap、SPEC-013、grading.ts、grading/summary.ts 与 app.ts。

## 展示方案

- 批次顶部只保留一份紧凑摘要：通过数/已判定数、失败数、异常数和进度；耗时、Token、费用作为次要信息，重试次数按 SPEC-021 展示。
- 有业务验收规则时优先显示“任务验收”；仅文本断言时显示“回复检查”。混合批次分别显示两类通过率，不把不同判定口径合并成一个无说明百分比。
- 没有文本判定样本时不展示“旧版文本通过率 — (0/0)”；无相关规则的关键约束、未判定约束不渲染空指标。异常为 0 时不平铺多个零值，仅正常状态摘要。
- 批次级默认不逐案例展开一整段验收指标。用户通过“详细统计”查看表格：案例、任务通过/已判定、验收覆盖、异常；全部成功比例、规则版本、技术字段与计算说明放入二级详情。
- 有错误、无法判定或必要规则失败时保留清楚的非零提示及定位入口；不能因为折叠而隐藏异常或让无样本显示 100%。
- 案例结果优先显示状态、简短失败原因、未通过必要检查。通过检查默认折叠；预期/实际有值才显示；证据与日志按需查看，复用现有预览区。
- 规则 hash 不作为默认标题，保留在“执行详情”；列表不新增内部案例 ID 或 session_id，session_id 仍在详情。
- 计算说明通过“统计口径”折叠入口展示一处，不在同页摘要、统计块下重复。窄屏自然换行，不输出横向长句。

## 截图场景的目标效果

```text
任务验收通过  1 / 1（100%）
[详细统计 ▸]  [统计口径 ▸]
```

失败场景则展示“任务验收通过 0 / 1 · 失败 1”，并可直接定位失败项。纯文本批次显示“回复检查通过”；运行中的样本单独展示进度，不作为已判定样本。

## 接口、兼容与异常

- 本项复用当前 gradingSummary，调整呈现层与显示选择，不改变现有任务判分、必要条件或原始导出字段。SPEC-021 引入重试后使用其统一最新执行选择器。
- 加载失败显示可重试状态，不以空数据冒充全通过；缺失费用、结果或历史字段显示准确的未知状态。
- 展开状态在实时刷新中保持，轮询不反复折叠用户正在阅读的内容；详情切换与筛选后对应内容正确更新。

## 验收标准与步骤

确认后标记 Approved；整理共用摘要和折叠统计，接入批次/报告/详情，更新说明。浏览器覆盖截图对应单案例全通过、纯文本、混合判分、全失败、验证错误、零案例、运行中与重试历史；检查 390px/桌面布局、键盘展开、轮询状态保持。运行类型检查和现有判分/报告回归，必要时为新的展示选择逻辑补充测试，不为静态样式新增镜像测试。记录结果后标记 Implemented。
