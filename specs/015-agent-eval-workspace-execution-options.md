## 1. 目标与当前行为

Web 完整任务统一调用 runIsolated：cwd 作为初始 fixture，复制到本轮运行数据目录的 workspace，随后 SDK 以该副本为 cwd/workspaceRoot；空 cwd 创建空副本。复制忽略 .git/node_modules/.cline/.eval-data，拒绝符号链接与源/运行目录重叠。

CLI 目前有区别：带 grading 的案例走同一隔离流程；不带 grading 的普通 CLI 案例直接使用 cwd。不能将现有所有 CLI 都描述为默认复制。

产物接口目前从 item.workspace 的父目录推断运行数据目录，再硬编码其 workspace 子目录。自定义复制目录与直接执行都会破坏这一假设，必须同时修改归档/产物读取。

目标：用户在完整任务的配置页选择执行方式，配置、执行目录和结果展示一致；原有未配置行为保持兼容。SDK 源码、单轮文字/函数调用行为不变。

## 2. 用户界面

完整任务“配置”页提供两种执行方式，切换时保留当前页面已填内容，按选中方式保存相关字段：

| 方式 | 必填/可选输入 | 行为 |
| --- | --- | --- |
| 复制后执行（Web 默认） | 初始工作区目录可选；副本保存根目录可选 | 复制初始目录到本轮独立目录后执行；初始目录仅作复制来源。未填初始目录使用空工作区，未填副本根目录保持原位置 |
| 直接在指定目录执行 | 执行目录必填且已存在 | 不复制，SDK 直接在该目录操作；修改保留在这个目录，不自动恢复或删除 |

复制根目录下每次运行生成唯一子目录，不覆盖根目录中的现有文件；界面说明“每个案例/轮次使用独立子目录”，并在执行结果显示最终实际路径。直接方式提示“本次任务会直接修改该目录；重复评测沿用当前文件状态”。这些是选项本身的说明，不增加每次运行确认弹窗。

单轮文字/函数调用不显示工作区选项、不操作这些任务目录；切回完整任务时仍可编辑之前配置。

运行配置也可保存默认方式。案例可覆盖默认设置，批次“使用运行配置”的现有流程继承新配置，输入快照/最终生效配置展示方式、初始目录和实际执行路径。

## 3. 配置合同

EvalDefaults 和 EvalCase 增加可选 workspace 对象：

```json
{
  "cwd": "D:/eval-fixtures/demo",
  "workspace": {
    "mode": "copy",
    "copyRoot": "D:/eval-workspaces"
  }
}
```

cwd 在 copy 时是初始目录；copyRoot 是副本根目录，实际路径为 copyRoot 下本次 run/item 对应的独立子目录。copyRoot 未指定时沿用运行数据目录/workspace。

直接方式：

```json
{
  "cwd": "D:/projects/demo",
  "workspace": { "mode": "direct" }
}
```

mode 只允许 copy/direct；direct 要求有效 cwd，不接受 copyRoot；Web 路径须为服务端绝对路径。CLI 路径按现有 suite/--cwd 解析规则处理，明确记录解析后路径。

case.workspace 存在时整体覆盖 defaults.workspace；cwd 仍遵循 case/default/CLI override 的既有优先级。单轮方式保留配置但不应用任务工作区策略。

## 4. 执行与兼容

- Web 以及已有 grading CLI：未设置 workspace 时继续复制到本轮默认目录。
- 普通 CLI 未设置 workspace：保留旧直接执行行为；明确配置 workspace 后使用新策略，与 Web 配置含义一致。文档说明这个旧版兼容例外。
- CLI 明确选择工作区策略但无 grading 时，也经过统一的工作区准备与结果归档；worker 内部执行必须绕开再次准备/派生进程，避免递归创建副本。
- direct 使用已存在目录的真实路径，不复制或删除文件；开始前建立 baseline，结束后归档 artifacts。验证器依旧在归档副本/临时目录运行，不能直接把真实工作区交给验收脚本修改。
- copy 自定义根目录必须创建唯一目标，复用现有复制过滤、文件/目录数量限制及错误处理。检查实际源/目标/运行数据路径，禁止递归复制、相互包含和覆盖源目录。
- 验收脚本和运行数据须在实际任务工作区外，复用现有隔离规则；冲突时在模型调用前明确指出目录问题及修正方法。
- 同一服务内，指向相同或相互包含的 direct 目录的评测按目录串行；锁持续到执行和最终归档完成，避免一个案例修改另一个案例的基线/产物。不同目录与独立副本仍可并发。其他应用或其他服务实例的文件操作不在此锁的协调范围，文档明确边界。
- direct 重复执行不会恢复原文件，后续轮次的 baseline 是该轮开始时状态；取消/失败保留已产生修改，不自动回滚。copy 每轮重新复制初始目录。

## 5. 结果与固定证据

持久化工作区描述（策略、初始路径、实际执行路径、所属运行数据目录）；RunItem.workspace 保留实际路径。产物 API 按已归属的 run/item 定位数据，不能再根据执行目录的父目录猜测归档路径。

新执行的文件列表、before/after 预览、Python artifacts/baseline 和历史试验证使用固定证据。尤其 direct 模式，后续任务或人工修改真实目录不能让旧结果变化。复制自定义目录也使用同一归档接口。旧执行可按原路径布局读取，不需要迁移旧历史。

结果页明确显示“直接执行 / 复制后执行”和实际目录，便于用户找到真实产物。目录元数据写入运行快照与导出；不把后台存储目录当作实际执行目录显示。
