# Agent Eval 跨模块复制与移动案例

状态：Implemented  
日期：2026-10-09  
范围：agent-eval Web UI、HTTP API、EvalStore 与相关回归测试  
确认记录：2026-10-09 用户回复“继续实施”，批准本方案范围。

## 1. 目标与范围

让用户在案例生成/保存后，可以复制到任意有效模块，或将原案例移动到其他模块，避免通过导出再导入整理案例。

首期同时支持单个案例和列表勾选后的批量操作，覆盖同模块复制、跨模块复制、跨模块移动、目标冲突预览、版本并发校验和历史快照保护。仅处理已保存的有效案例，不引入模块嵌套、拖拽排序或案例共享引用。

沿用根目录 spec 流程；已阅读 AGENTS.md、内网 roadmap、现有结果判分 spec、请求头 spec 及 Store/API/UI 源码。不改 SDK、不新增脱敏、不改变模型执行和判分。

## 2. 当前行为与限制

- 列表中的“复制”调用 POST /api/cases/:id/duplicate，不传目标模块。
- EvalStore.duplicateCase 固定使用 source.moduleId，生成 `<原案例ID>-copyN`，创建新内部 ID、revision=1 的副本。
- 已有案例保存接口 PUT /api/cases/:id 只更新 definition/defaults，不允许改变 moduleId。
- 同模块有效案例以 definition.id 判断重名；SavedCase.id 是内部 UUID，用于引用案例和关联历史。
- 列表已有勾选和批量评测工具栏；案例详情目前没有复制/移动入口。
- RunItem 保存提交时的 SavedCase snapshot 和 moduleName。历史记录按 snapshot.id 关联，运行队列使用快照，不实时读取案例。

## 3. 操作入口与交互

### 单个案例

- 列表行“复制”打开“复制案例”弹窗，允许选择目标模块，默认原模块，保留当前复制能力。
- 同行增加“移动”入口。移动弹窗默认提示选择其他模块，不预选目标，避免误操作。
- 已保存案例详情页增加“复制到模块…”和“移动到模块…”入口，复用相同弹窗；新建但未保存的案例不显示。
- 若详情页有未保存修改，提示先保存后操作，不自动保存、丢弃或复制表单中的草稿。

### 批量操作

- 勾选后工具栏增加“复制到模块…”和“移动到模块…”。可选案例来自同一个或多个模块。
- 弹窗明确显示选中总数，操作全部已选案例，不只操作当前筛选中可见的案例。提示包含隐藏选择，避免误解操作范围。
- 所有案例必须一次成功，不部分移动/复制；失败时保留选择，用户修正后重试。

### 弹窗结构

1. 标题与说明：复制保留原案例，移动改变归属。
2. 目标模块选择器：只提供未归档模块，显示模块名称和有效案例数。
3. 重名处理：自动生成新案例 ID / 遇重名停止。复制默认自动生成，移动默认遇重名停止。
4. 预览列表：原模块、案例名称、目标模块、是否重名、拟采用的案例 ID。仅在此类编辑/冲突场景展示业务 definition.id，不在常规案例列表新增内部 UUID/session_id。
5. 确认按钮：“复制 N 个案例”或“移动 N 个案例”，请求期间禁用，防止重复点击。

更换目标或冲突策略时重新预览。所有 ID 变化在确认前可见，不覆盖目标已有案例。预览不启动评测，也不修改数据。

## 4. 数据与历史规则

| 行为 | 内部 SavedCase.id | moduleId | definition.id | revision | 历史 |
|---|---|---|---|---|---|
| 复制 | 新 UUID | 目标模块 | 无冲突时跨模块保留，冲突时按策略处理 | 1 | 不继承原案例执行历史 |
| 移动 | 保留 | 目标模块 | 默认保留，显式自动重命名时可改 | 原值 + 1 | 保留并继续关联 |
| 移动到当前模块 | 保留 | 不变 | 不变 | 不变 | 不变，记为无需移动 |

- prompt、history、replayMode、tags、description、assertions、grading、工具/迭代/超时配置、fixture 路径、systemPrompt、默认模型配置及两层 headers/headersEnv 全部深拷贝保留。跨模块操作不改用当前全局配置或目标模块的其他案例配置。
- 新副本和原案例互不引用可变对象。复制不带 archived=true，也不继承执行结果。
- 移动更新时间，并增加 revision，使旧编辑窗口保存时触发原有 409 版本冲突，避免覆盖移动结果。
- 旧 RunItem 的 snapshot、moduleName、revision、输出和 artifact 路径均不回写；排队中/运行中的任务继续按原快照执行。
- 后续提交的任务使用新模块归属。历史重跑仍用旧快照；移动后的案例详情可以继续查看原历史，历史中的模块名称表示执行时归属。
- 模块案例数量、列表筛选和新建评测选择器在操作后刷新。移动保留原案例的最新结果关联；副本显示“未运行”。
- 不迁移工作区/运行目录，不复制已运行产物或服务器环境变量值。仅复制配置中的环境变量名称。

## 5. 重名规则

- 按现有规则，仅在目标模块的有效案例中检查 definition.id 精确相等，不改变全仓库的大小写或归档冲突语义。
- 同模块复制继续从 `<原ID>-copy1` 开始寻找空位，兼容旧能力。
- 跨模块复制或移动优先保留原 ID；目标已有同名案例时，自动模式采用最小可用 `<原ID>-copyN` 或 `<原ID>-moveN`，停止模式阻止整个操作。
- 一次批量操作中的新名称也参与保留集合。例如不同源模块各有同名案例，复制到同一目标时后一个也会被识别为冲突，不允许生成两个相同 ID。
- 不提供覆盖已有案例模式；避免复制/移动变成隐含内容替换。
- 批量移动时已在目标模块中的案例记为 unchanged，不改版本；其他案例照常预览。全部 unchanged 时不执行写入，界面提示“所选案例已在目标模块”。

## 6. API 与存储设计

新增统一预览接口：

```http
POST /api/cases/transfer/preview
Content-Type: application/json
```

```json
{
  "operation": "copy",
  "targetModuleId": "目标模块内部ID",
  "conflictPolicy": "rename",
  "items": [{ "id": "源案例内部ID", "revision": 3 }]
}
```

- operation 为 copy/move；conflictPolicy 为 rename/abort。1–1000 个不同源案例，重复内部 ID 报错，避免请求意外重复复制。
- 返回每项源 revision、原业务 ID、拟采用的业务 ID、源/目标模块名称、结果 copy/move/unchanged，以及整体 canApply、冲突摘要和有效操作数。
- 在返回结果中引用内部 ID 供前端操作，界面不直接展示这些 UUID。

新增执行接口：

```http
POST /api/cases/transfer
Content-Type: application/json
```

执行 body 与预览相同，每个 item 另带预览中的 `expectedDefinitionId`，代表用户确认的目标业务 ID。Store 在单个 SQLite 事务中重新校验并生成计划：

1. 源案例存在、未归档，源模块未归档，revision 与请求一致。
2. 目标模块存在且未归档。
3. 使用事务内实际目标案例重新计算名称，结果必须与 expectedDefinitionId 一致；预览后出现新冲突或名字空位改变，返回 409 要求重新预览，不静默改名。
4. 全部校验成功后才一次写入；任何失败均回滚。

成功返回新/更新的 SavedCase 数组和 copied/moved/unchanged 计数。对 unchanged 项同样校验源 revision 与确认的业务 ID。

保留旧 POST /api/cases/:id/duplicate 的无 body 调用语义，用新的存储能力或兼容封装继续同模块复制，避免破坏现有调用者。旧入口按原行为附加“（副本）”说明；新统一操作复制完整 description，不自动改文案。

无需数据库迁移；records 已保存 moduleId/revision。继续使用同源请求约束和现有 JSON 校验机制。

## 7. 并发、异常与恢复

- HTTP 400：非法操作/策略、空选择、重复选择、超量、缺字段或不合法数据。
- HTTP 404：源案例或目标模块已删除。
- HTTP 409：源 revision 改变、模块被归档、预览名称已失效，或停止模式发现目标重名。消息说明具体源案例/模块和处理方式，不仅显示“操作失败”。
- 客户端收到 409 保留目标/策略和选中案例，重新加载预览；禁止自动重试写入。
- 没有其他有效目标模块时，移动按钮禁用并提示先创建模块；复制仍可到当前模块。弹窗可以关闭，不直接增加模块创建流程。
- 单次提交期间锁定按钮。若网络中断导致提交结果未知，不自动重复复制，先刷新目标模块核对结果；首期不增加通用幂等任务系统。
- 操作成功后关闭弹窗、清除已处理的选择并刷新计数。列表保留当前模块筛选，并提供“查看目标模块”动作；详情移动后刷新相同案例页面的面包屑，复制后提供“查看副本”。

## 8. 验收标准

1. 同模块复制、跨模块复制、单个移动、混合源模块批量复制/移动均能正确执行。
2. 内容和配置完整保留，包括 grading、fixture、请求头字面值和环境变量引用；修改副本不影响原案例。
3. 移动保留内部身份和历史；复制创建新身份且无历史。排队中和正在执行的快照、旧导出/历史重跑不改变。
4. 重名预览与写入一致，批量内部冲突可识别，rename/abort 策略符合规则，不覆盖目标已有内容。
5. 预览后修改/删除案例、归档模块或新增目标重名案例时，提交失败且无部分写入；移动后旧窗口保存返回 409。
6. 目标模块内的 unchanged 项不改版本；全部 unchanged 不写入。
7. 旧 duplicate 接口继续通过原测试，不要求现有调用者新增 body。
8. 浏览器验证列表/详情/批量入口、窄屏弹窗、未保存修改提示、重复点击禁用、错误后保留输入，以及成功后的计数与导航。
9. Store/API 相关测试、配置/历史回归测试、typecheck、Web bundle 与 git diff --check 通过。不需要外部模型、凭据或修改 SDK。
