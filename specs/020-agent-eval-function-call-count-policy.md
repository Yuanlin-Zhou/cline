## 1. 当前行为与目标

现有单轮函数调用只发送一次模型请求，不执行返回工具。一次响应的 message.tool_calls 本来就是数组，运行器支持多个调用。functionCall.tools 配置公布工具，toolChoice 支持 auto、required、具体工具名，前端已有选择器，具体工具名会生成标准 tool_choice function 对象。

六个 Python 验证器会逐个验证本轮所有调用的唯一非空 ID、type=function、工具名、arguments JSON 和请求公布的参数 Schema。但 expected_count 默认为 1，最终要求目标工具准确调用一次；不是运行器只接受一个调用。现有 expected_count=2 可要求准确两次，但不能表达至少一次、不限具体次数。

目标：保留单次模型响应语义，明确指定工具、验证每个调用格式，允许可变数量的同一工具调用。多请求、实际执行工具后继续对话、自动补工具结果不在此范围。

## 2. 指定工具方式

- 提示词指定：例如“请使用 editor 修改这两个文件，允许分别调用多次，不要用自然语言代替工具调用”；toolChoice=auto，验证器检查是否实际返回目标工具。
- 推荐约束：tools=[editor]，toolChoice=required；仅公布 editor，要求返回工具调用，最终仍由脚本核验名称及格式。网关须支持该 tool_choice 语义。
- 可选具体工具名：沿用 toolChoice=editor，发送强制指定函数的协议字段；不同模型服务对强制具体函数与多个调用的兼容性可能不同，不能承诺每个服务都会生成多个。

前端补充短提示，区分“本轮只请求一次模型”和“响应可以包含多条工具调用”，说明强制协议不能证明自动选择能力。不会自动篡改用户提示词或全局强制所有案例改成 required，也不强制新增可能不兼容网关的 parallel_tool_calls 字段。

## 3. Python 调用次数策略

新增可选参数 min_count、max_count，表示目标工具调用数下限/上限：

- {"min_count":1,"allowed_tools":["editor"]}：至少一次 editor，接受多次；不设置 expected_total_calls。
- {"min_count":1,"max_count":5,"allowed_tools":["editor"]}：一至五次。
- 现有 {"expected_count":2}：准确两次，语义不变。
- expected_count 与 min_count/max_count 同时配置报参数错误，不静默覆盖。
- min_count 为正整数；仅设置 max_count 时下限为 1；max_count 须为正整数且不小于下限。
- 未配置任一新增计数参数时继续沿用旧 expected_count 默认 1，避免旧案例静默放宽；新示例明确传 min_count=1。
- expected_total_calls 仍是可选的总调用精确约束，不为“至少一次”示例填写；显式配置时与目标计数约束须逻辑相容。

所有实际调用都校验，不会只看首条、遇到一条正确就通过。允许列表仅 editor 时混入 read_files 等调用失败；任意重复 ID、非法参数、缺字段均失败。无工具调用失败。超过已有 15 项证据处理上限继续报告 insufficient，不声称无限条可验证；UI/README 清楚说明该技术上限。

检查结果显示“目标工具至少 1 次，实际 3 次”等可读信息，并保留每个调用的失败路径。检查原始归档响应，不把提示词中的伪 JSON 或历史调用当成本轮输出，也不执行真实工具。

## 5. 异常与验收
