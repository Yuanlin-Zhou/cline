## 1. 当前行为

模块仅支持归档，没有永久删除；案例支持单个永久删除，但没有批量入口。案例列表已有勾选和转移操作，可复用选择状态。上传验证脚本仓库目前仅有 list/get/create，界面支持上传、选择及历史试验证，没有集中管理和编辑删除。文件配置注册的验证器由配置文件维护，不能当作上传脚本直接修改。

执行项已固定案例、模型配置和验证器源码快照；删除当前案例或修改脚本不应改变已提交任务和历史结果。MongoDB 存储模块/案例/上传脚本，运行记录仍由既有本地存储管理；SQLite 部署同样支持全部入口。

## 2. UI 与操作流程

### 2.1 删除模块及全部案例

在模块操作区增加“删除模块”，保留原“归档”入口。打开确认框显示模块名、模块内全部案例数量（包含已归档案例），明确“永久删除模块及全部案例；保留历史评测、执行快照与归档产物”。需输入模块名称后才启用最终删除按钮。

提交前取得模块和案例清单预览；提交时校验预览的案例集合及版本。期间案例新增、移动或修改导致清单变化时返回冲突，展示更新后的数量，重新确认，不能悄悄多删。删除成功返回案例集并显示删除数量；失败保留对话框和错误，不显示成功。

### 2.2 批量删除案例

案例列表已选至少一个案例时显示“删除所选（N）”，复用现有选择机制；明确“全选当前筛选结果”作用范围，不隐藏选择筛选外案例。确认框显示数量及案例名称、所属模块，列表较长时滚动展示，避免弹窗过长。

客户端提交明确的案例 ID 与 revision，服务端全量校验后一次事务删除；不存在、版本变化、重复 ID、非法数量均返回可定位错误，不循环调用单例删除接口造成部分成功。首期限 1–1000 个；取消不写入。成功清除选择并刷新模块数量/列表；失败保留选择并提示刷新核对。

### 2.3 Python 验证脚本管理

增加可直达的“验证脚本”管理页，在案例判定规则的脚本选择旁和批量导入的 Python 选择旁提供“管理脚本”入口，不把编辑器塞进规则表单。列表展示名称、文件名、Python 类型、内容版本和被引用案例数量；提供搜索、上传、查看/编辑、下载、删除。

仅管理用户上传的 `.py` 脚本。配置注册程序展示来源提示及只读信息，JS/TS 保持现有兼容能力，不在本次新增其编辑入口。

编辑面板包含显示名称、文件名、源码编辑区域，也支持选择新 `.py` 文件替换源码；提供“保存”和“取消”，未保存离开时提醒。保存须进行 UTF-8/大小/文件后缀/`def verify(ctx)` 入口及 Python 语法检查；只检查，不执行脚本、不安装依赖。Python 不可用时禁止保存修改并给出环境提示，保留编辑内容。

编辑保留 verifierId，按源码重新计算 version/sha256。保存前列出引用案例数量并提示“这些案例下次新建运行使用新脚本；已提交运行和历史结果仍使用原快照”。不改写所有案例版本、不自动重新判分。保存成功刷新选择器，现有绑定无需重选。以读取时的资源状态令牌作乐观并发校验，另一个页面已修改则返回 409，禁止覆盖最新内容。

删除前检查全部当前案例引用（包含已归档案例），显示具体引用及跳转入口：**仍被引用时禁止删除，先到这些案例移除或替换验证器再删除**，避免留下失效规则。删除确认显示名称和文件，说明历史快照仍保留。无引用时永久删除当前脚本，后续列表不再提供；历史快照的查看、试验证及既有快照重跑仍沿用原逻辑。未保存草稿无法全局枚举，若其脚本已删除，保存/发起运行须给出明确缺失提示，不自动去掉规则或改成通过。

## 3. API 与数据访问

建议接口（实施中可按既有路由风格细化字段）：

- `POST /api/modules/:id/delete-preview`：返回模块、全部案例清单/版本及数量。
- `DELETE /api/modules/:id`：请求体带已确认清单/模块状态令牌，在事务内校验后级联删除案例与模块。
- `POST /api/cases/delete-batch`：`{items:[{id,revision}]}`，事务内全量校验与删除，返回删除数量。
- `GET /api/verifiers/:id`：返回可管理的脚本源码、状态令牌及引用列表。
- `PUT /api/verifiers/:id`：`{expectedToken,label,filename,content}`，只允许上传 Python，验证后原子比较并替换。
- `DELETE /api/verifiers/:id`：携带 expectedToken，校验引用及资源状态，删除并返回结果。

扩展 CatalogRepository 的模块级联/批量删除与 VerifierRepository 的更新/删除。SQLite 使用现有数据库事务，MongoDB 使用现有副本集事务，级联操作同步参与模块并发保护，避免和案例创建/转移交错产生孤儿记录。脚本更新/删除使用原子条件写，冲突不覆盖。引用检查失败不变更案例规则。

引用检查不承诺跨两个仓库的全局锁；并发写入的新引用或未保存草稿可能在删除后遇到不存在的验证器，统一由保存和运行前校验明确阻止，不允许静默漏判。运行已经取得的源码快照保持有效。

状态令牌可按脚本现有完整可编辑状态和摘要计算，不新增必需字段；不修改现有内容哈希 version 的含义。优先沿用现有集合/文档合同，不要求迁移。若实现核查发现必须变更合同，先更新本方案说明具体准备步骤，不自动回退存储模式。

## 4. 兼容与错误

- 现有单案例删除、归档、上传、批量导入和重跑保持可用；归档与永久删除含义清楚区分。
- 不删除 run/item、历史脚本快照、产物归档或用户指定工作目录；已提交任务继续使用快照。
- 活动和已归档案例都计入模块删除范围及验证脚本引用检查；管理页必须能够定位归档引用，不能显示不可处理的死链接。
- 超时/断网时明确“未确认删除成功”，保留所选项，提示刷新核对；防重复点击。缺失返回 404，状态冲突/仍被引用返回 409，无效输入返回 400/422，超限返回 413，数据库故障不能显示部分成功。
- 脚本更新保留 ID，引用案例未来执行使用新版本；旧运行用旧版本。源码或标签只改一项也应检测并发更新。

## 5. 验收标准

1. 非空/空模块、含已归档案例模块可删除；取消和模块清单过期均零写入；数据库中途失败整批回滚，无孤儿案例。
2. 跨模块选定案例可原子批量删除；非法/缺失/过期项阻止整批；未选项不受影响；原单例删除不回归。
3. 上传 Python 能查看、编辑、替换文件、下载和删除；非法语法/入口/编码不能保存，Windows UTF-8 回归通过；配置注册及 JS/TS 不被错误编辑。
4. 编辑后 verifierId 不变、摘要匹配源码；引用案例下一次使用新版本，已提交/历史执行使用原快照；双窗口修改/删除冲突明确。
5. 被引用脚本删除被阻止并可定位引用；解除引用后可删除；缺失脚本不能使运行默默漏判；历史快照试验证和重跑不依赖当前脚本仍存在。
6. MongoDB 与 SQLite 对等接口测试、事务失败测试；没有 Mongo 实库时明确记录跳过。浏览器验证完整流程、错误保留、键盘操作和窄屏。
