# 如何配置判定规则

进入 **案例详情 → 判定规则**，先选择要检查的内容。所有标为“影响通过”的检查都须满足，才算本次评测通过。未配置内容检查时，系统只检查是否正常结束，不能据此证明业务任务完成。

## 选择检查目标

| 入口 | 适合检查什么 | 需要填写什么 |
| --- | --- | --- |
| 最终回复 | Agent 最后一条回复是否满足文字要求 | 包含的文字，每行一项；可按需添加不包含或正则检查 |
| 文件产物 | 交付文件存在、禁止额外文件、保护初始文件、文字或 JSON 内容 | 工作区内相对文件路径及检查条件；需要完整任务模式 |
| Python 脚本 | 自定义结果、会话与文件的业务验证 | 选择已有脚本，或“上传 .py”；编写帮助和模板见“编写指南” |

例如要求交付 `out.txt` 且包含 `hello world`：点击“文件产物”，根据提示切换到完整任务，选择“文件内容符合要求”，填写路径 `out.txt`、判断方式“包含”、期望文本 `hello world`。文件缺失也不能通过，不必另加存在检查。

检查 JSON 时先填文件，再填字段路径（例如 `/total`），选择判断方式和值类型。数字 `12` 与文字 `12` 不同；“字段存在”无需期望值；“数值近似”至少填写一种允许误差。复杂字段路径与相对误差说明按需展开。

## 保存与错误修正

每张检查卡显示通过条件与“影响通过”开关；不勾选则仅作参考。文件或脚本验收至少须保留一项影响通过的检查。保存前会标出具体错误，展开相关设置，并定位第一个需修正的输入项。

切换执行模式不会清除规则，不兼容的规则会显示提示。取消“启用文件与脚本检查”会在当前页面保留表单内容，但保存后这些规则不会写入案例；重新打开案例不保留已禁用的配置。最终回复检查独立保存。

## Python 的日常操作

1. 点击“Python 脚本”，选择已有脚本或“上传 .py”。
2. 不知道怎么写时打开“编写指南”，选择最终回复、产物或会话模板，下载后修改 `verify(ctx)` 的业务逻辑。
3. 需要参数时展开脚本“高级设置”，填写 JSON 对象，脚本用 `ctx["params"]` 读取。
4. 保存案例，从案例列表运行已保存案例；之后点击“试验证”，选择历史执行，查看输入、结果和日志。不会再次调用模型或覆盖原结论。

案例详情的未保存调试使用独立草稿，不会出现在该已保存案例的试验证历史中。详细协议见 [Python 验证脚本说明](python-verifiers.md)。

## 高级设置

结束状态、维护者注册的验收程序、工具行为诊断和整体 JSON 编辑在“高级判定设置”中。当前工具行为诊断不能验证真实工具执行或审批行为，只能作为参考。

整体 JSON 只编辑文件、脚本和诊断检查；编辑后需“应用 JSON”，确认替换，再保存案例。非法 JSON 与取消替换均保留当前表单，最终回复检查不受替换影响。“重新载入表单”会用表单当前值覆盖 JSON 编辑框。

## 查看结果

结果先显示验收结论与必要检查通过数，未通过的必要检查自动展开，展示原因、可用的预期/实际值和下一步建议。脚本检查项可独立展开；“日志与相关证据”按需加载并复用预览区域。“检查详情”及“执行与规则版本”提供内部标识与诊断信息。

“修改判定规则”返回已保存案例。正常通过、业务失败、证据不足与验证错误各有不同含义；脚本错误应先看运行日志，修正后用历史结果试验证。
