# 批量历史对话导入示例

启动 Web 后进入 **案例集 → 导入案例 → 历史对话 JSON（批量生成案例）**，选择目标模块，多选本目录的三个 `.json` 文件，点击“校验并预览”，检查对话和本轮输入后确认导入。不要选 README；这些文件是原始会话，不是旧入口需要的案例集。

| 文件 | 格式与实际末条 | 生成的本轮输入 |
| --- | --- | --- |
| `01-user-tail.json` | Cline 原生，末条是普通用户消息 | 使用原末条“把 demo.py 中的 hello 改成 world，使用 editor 工具。”；不再追加消息 |
| `02-assistant-tail.json` | 标准 function call，末条是助手回复 | 保留所有原历史（包括最后的助手回复），追加用户“继续” |
| `03-tool-tail.json` | type/data 包装，末条是已闭合的工具结果 | 保留所有原历史，追加用户“继续” |

可将公共“追加的本轮输入”改成“请继续修改 demo.py，使用 editor 工具”，也可以单独填写每个文件的续接文案；末条已经是普通用户消息的文件仍直接使用原末条。不会向前找用户消息并丢弃其后的工具结果或助手回复。

默认启用六个工具，可在“调整本轮工具”中仅保留 editor。按需选择已上传的 Python 验证器；未绑定时只创建案例，不自动生成验证规则。函数调用验证器的上传和准备方式见 [../function-calls/README.md](../function-calls/README.md)。运行需要 OpenAI-compatible 模型连接，配置使用打开导入页时的运行配置快照。

这些示例仅回放工具轨迹，不读取或创建真实 demo.py，也不执行历史工具。预览和导入都不请求模型；导入后需要手动运行案例。

每批最多 100 个 UTF-8 JSON 文件（允许 BOM），单文件 1 MiB/500 条原始消息，内容合计及提交请求各不超过 20 MiB。未闭合工具调用、断链、非法 JSON、未确认的思考内容等会定位到文件；有任何错误时整批不写入，修复或明确移除错误文件后重新预览。同批重复 ID 必须修正；目标模块已有同名案例可选择跳过或创建新版本。修改设置后须重新预览。

MongoDB 与 SQLite 均复用现有事务，无需为本功能增加数据库迁移；部署须已支持原生历史字段。单案例粘贴导入仍支持手动选择回放位置，其截断选项与本批量入口不同。
