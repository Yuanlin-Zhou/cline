# 参考答案与 LLM Judge

LLM Judge 在被测模型执行结束后，使用独立模型比较参考答案和所选材料，输出 0–100 分、理由与原文依据。支持普通单轮、完整任务和单轮函数调用。默认只提供评分，不改变原有通过/失败结果。

## 页面操作

1. 在 **运行配置 → 全局 Judge 默认模型** 保存评审 Provider、模型、Base URL、密钥环境变量及可选自定义请求头。它与被测模型的全局配置分开保存。
2. 打开案例的 **判定规则 → LLM 评分**，填写参考答案；可附加自然语言评分标准，例如“重点检查事实正确和覆盖全部要求，允许不同表达”。
3. 勾选 **执行结果**、**执行轨迹**或两者。Judge 模型中点击 **使用全局 Judge 配置**；也可手动选择其他模型，或主动复制当前执行模型配置。
4. 保存案例并正常评测。执行完成后先做原有确定性判分，再显示 **LLM 评分中**。结果区顶部与 **LLM 评分**页签显示评分卡，展开依据或点击 **查看实际送审材料**可复核。

全局 Judge 模型仅作为选择时的模板；保存案例后模型配置随案例冻结。以后修改全局默认值不会改变已有案例、排队任务或历史执行。未启用评分的案例不会调用 Judge。密钥字段填写环境变量名称，实际值由服务进程读取；更改服务进程中的凭据后按原方式重启服务。

## 哪些材料会送审

| 选项 | 内容 | 边界 |
|---|---|---|
| 执行结果 | 最终回复；可另外指定归档文本文件 | 不选文件时不会发送整个工作区 |
| 执行轨迹 | 已保存的会话、工具请求/返回，或原始函数调用请求 | 保存的主会话可能压缩；通知不证明真实执行或审批 |
| 题目上下文 | 任务指令及原始案例历史 | 始终提供，用来理解题目 |

未选轨迹时不发送本次会话/工具诊断；未选结果时不另外发送本次最终回复或产物正文。参考答案与评分配置不会注入被测模型的提示词、初始历史或 worker 输入。

完整任务的高级设置可以指定最多 20 个工作区相对文件路径，每行一个，例如 `output/report.json`。只读取归档中的 UTF-8 文本，单文件不超过 64 KiB，检查其哈希，不读取当前正在变化的工作区。单轮模式不提供文件产物评分。

当只有保存的压缩上下文时，评分会注明完整性未知；完全缺少所选轨迹、文件缺失或证据不一致时不自动退回到只评最终回复。输入默认上限 128 KiB，可调整至最多 1 MiB；超限停止评分，需缩小范围，不会静默截断或额外付费调用模型做摘要。

## 分数和通过状态

默认 **仅评分**：即使分数低、Judge 服务报错或材料不足，原案例结论也保持不变，评分卡和覆盖统计会单独显示。

如勾选 **影响通过结果**，可以设置 0–100 的及格分，默认 80：

- 原检查通过且评分达到阈值：通过。
- 原检查通过但分数低于阈值：断言失败，原因是 LLM 评分未达标。
- 原检查通过但 Judge 返回无效响应、服务异常或信息不足：无法判定，不当成 0 分或通过。
- 原确定性检查已经失败或无法判定：不会因为 Judge 给高分升级成通过。
- 被测执行基础设施出错或运行取消：默认跳过自动评分；可用已有历史材料另做试评分。

Judge 的判断基于参考答案、评分标准和实际送审材料；轨迹缺失的步骤不会因高分而变成已发生的事实。分数不会提供模型隐藏推理，也不保证同一模型多次调用得到完全相同结果。

## 使用历史结果试评分

在案例 LLM 配置卡点击 **试评分**，选择一次已结束的执行，先 **预览送审材料**，再 **开始试评分**。这里使用当前编辑的参考答案和 Judge 配置，只调用 Judge，不调用被测模型，也不修改原正式成绩、通过率或案例库。

预览不调用模型。正式开始试评分会产生模型用量；结果明确标记为试评分。关闭面板不自动取消后台任务，重新打开可恢复当前任务；需要停止时点击 **停止试评分**并等待返回。重复提交相同请求不会重复创建评分，服务重启会将未完成试评分标为中断，不会自动再次调用模型。

旧执行如果没有对应归档材料，会提示所选范围不可用，不用现在的工作区替代历史事实。试评分不支持“覆盖成正式成绩”；要用新参考答案产生正式成绩，保存案例并新建评测。原批次内重试仍沿用当初冻结的参考答案和模型，重跑整个案例。

## 模型、成本与导出

Judge 使用现有模型 Provider 接口，不带工具，也不启动可执行命令/修改文件的第二个 Agent；CLI 编码 Agent Provider 不用作 Judge。OpenAI 兼容网关同样支持 `headersEnv` 和已有 `{{requestId}}` 等请求头模板。Judge 不从被测案例的模型字段中自动取密钥或请求头。

原执行用量字段保持原语义，Judge 的 Token、费用和耗时独立记录；费用未提供时显示未知。批次均分按 Judge 模型和评分标准分组，未评分/错误不会当成 0 分参加均分。重试后默认统计各案例各轮的最新评分，旧尝试仍可查看；正式评分成本累计所有尝试。试评分成本只在其独立记录中显示。

JSON 保留完整 Judge 结果及配置快照；CSV 增加分数、状态、范围、阈值、理由、模型、记录 ID、输入/配置摘要和用量；Markdown 提供评分摘要。评分引用的 source ID 仅用于定位这次实际送审材料，不作为常规案例列表中的业务字段展示。

## JSON / CLI 示例

完整示例见 [`examples/llm-judge/suite.json`](../examples/llm-judge/suite.json)。先替换两个模型名和服务地址，并在服务环境配置相应凭据：

```sh
export ACTOR_API_KEY='替换为被测服务密钥'
export JUDGE_API_KEY='替换为评审服务密钥'
bun run eval examples/llm-judge/suite.json --output results/llm-judge.json
```

`llmJudge` 是案例字段，必须指定其独立 `model`；JSON 导入不会隐式继承当前被测模型或全局 Judge 配置。`enabled: false` 可保留已填内容并停用。只希望看分数时保留 `affectsOutcome: false`；需要及格线时显式开启。

评分使用结构化 JSON。分数越界、缺必需字段、引用了未送审材料或虚构原文片段，都记为评分错误。应用层不额外调用模型自动修复坏响应，也不因此自动重跑被测案例。超时默认 120 秒，可在 1–300 秒范围内调整；与被测任务超时独立。

## HTTP 接口

- `GET /api/judge-settings`、`PUT /api/judge-settings`：独立 Judge 默认模型配置。
- `POST /api/runs/:runId/items/:itemId/judge-scores/preview`：body `{ "config": { ...完整 llmJudge 配置 } }`，返回将送审的材料，不调用模型。
- `POST /api/runs/:runId/items/:itemId/judge-scores`：body `{ "requestId": "UUID", "config": { ... } }`，创建幂等试评分任务。
- `GET /api/runs/:runId/items/:itemId/judge-scores`：列出该执行的试评分；`GET .../:scoreId` 查询任务，`?input=1` 附带冻结输入；`POST .../:scoreId/cancel` 停止。
- `GET /api/runs/:runId/items/:itemId/judge-scores/official-input`：查看该执行已保存的正式送审材料。

任务 `completed` 仅表示处理结束，需查看 `result.status` 区分已评分、信息不足或评分错误。相同 requestId 更换配置返回 409。试评分记录保存在本地运行数据库，案例库仍遵循 SQLite / MongoDB 配置。

已有 MongoDB 部署更新后先执行 `bun run mongo:prepare` 更新案例校验器，再启动 Web；SQLite 无需破坏性迁移。模型服务与凭据仍按当前运行环境配置，应用不会绕过环境的网络策略。
