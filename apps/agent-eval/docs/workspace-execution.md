# 完整任务的工作区执行方式

在 **案例详情 → 多轮回放（完整任务）→ 配置 → 工作区执行方式** 选择；“运行配置”也可设置新案例的默认方式。单轮文字回放和单轮函数调用不应用任务工作区设置。

| 方式 | 填写 | 实际执行 |
| --- | --- | --- |
| 复制后执行 | 初始工作区目录可选；副本保存根目录可选 | 每次准备独立副本，SDK 的 cwd/workspaceRoot 指向副本 |
| 直接在指定目录执行 | 已存在的执行目录必填 | SDK 直接读写这个目录，不复制、不自动恢复或清理 |

Web 路径是**服务器所在机器的绝对路径**。留空初始目录时从空副本启动；副本根目录留空时仍使用本轮运行数据目录下的 `workspace`。自定义根目录下创建带运行/案例标识和随机后缀的独立子目录，不覆盖用户已有目录。结果页显示实际执行目录。

复制保留原过滤规则：不复制 `.git`、`node_modules`、`.cline`、`.eval-data`，拒绝符号链接，限制 10000 个目录/文件。直接执行保留原目录及其依赖；产物归档仍按既有过滤和限额处理，符号链接或超限等会使证据不完整。

复制策略设置了 SDK 工作目录，不是操作系统沙箱。评测任务与命令应面向实际副本路径，避免显式指向原始目录。直接方式的修改会保留，取消和失败不会自动回滚。

## JSON 配置

复制到指定根目录：

```json
{
  "replayMode": "full-task",
  "cwd": "D:/eval-fixtures/demo",
  "workspace": { "mode": "copy", "copyRoot": "D:/eval-workspaces" }
}
```

直接执行：

```json
{
  "replayMode": "full-task",
  "cwd": "D:/projects/demo",
  "workspace": { "mode": "direct" }
}
```

Linux 可使用 `/opt/eval-fixtures/demo` 等路径。`workspace` 可放在案例或 defaults 中；案例存在该对象时**整体覆盖** defaults 的对象，`cwd` 仍按案例/defaults/CLI override 的既有优先级解析。direct 不接受 copyRoot，也不能缺少有效 cwd。Web 会拒绝相对路径；CLI 文件中的路径按案例集所在目录解析，`--cwd` 按终端当前目录解析。

目录不得与本次运行数据目录相互包含；验收脚本应位于任务工作区之外。遇到冲突，将 `EVAL_DATA_DIR` 或脚本目录配置到工作区外，再执行。所有工作区准备错误都会在调用模型前结束该执行。

## 并发与重复执行

同一服务进程内，对相同或相互包含的直接执行目录加锁，直到模型执行、验收和归档结束；其他独立目录及副本仍可并发。此协调不覆盖其他服务实例或人工操作。

复制方式每轮重新从初始目录准备副本。直接方式的下一轮使用当前目录状态，不恢复第一轮输入：上一轮的修改会成为下一轮的基线。需要独立重复对比时选择复制方式。

## 产物与历史

直接方式和自定义副本方式均保留运行前 baseline、运行后 artifacts 和实际目录描述。新运行的“文件产物”列表与文本预览使用固定归档；人工后来修改或删除真实目录，不会改变旧执行结果。归档不完整时明确提示，不能据此推断文件缺失或通过验收。

Python/注册验收程序仍在归档副本或临时目录验证，不直接修改原工作区。历史脚本试验证也读取固定输入，不重新调用模型。旧运行记录保留原路径布局的读取兼容。

## CLI 与部署兼容

- Web、已有带 grading 的 CLI：没有 workspace 配置时保持默认复制。
- 旧普通 CLI（无 grading、无 workspace）：保留原直接使用 cwd 的行为。
- CLI 明确指定 workspace 后使用选择的策略，即使没有 grading；worker 使用已经准备的目录，不会递归再次复制。
- SQLite 无需结构迁移；已有 MongoDB 部署升级后运行 `bun run mongo:prepare`，使新 workspace 配置符合集合校验器。

`examples/workspace-execution/suite.json` 提供复制与直接方式的配置模板。先将示例中的目录替换为服务器实际路径，再导入；例子使用只读工具范围，仅展示工作区和文件读取，不主动要求写入文件。
