## 1. 目标与范围

调整案例编辑页的判分区域及逐项判分详情，复用现有视觉规范；添加一组可在案例列表打开、修改和运行的示例。规则语义、判分引擎、SDK 和统计口径保持现有约定。

## 2. 当前行为与问题

`src/web/client/grading.ts` 使用标签直接包裹控件、纵向排列类型选择和添加按钮，规则主要通过 JSON 编辑。结果与行为分组即使为空仍展示裸标题；高级编辑器占据较大空间。全局 details 样式添加箭头，浏览器原生标记也可能同时显示。

现有页面已有 Box/Box-header、form-row、btn、Label 和颜色变量，判分区域尚未一致复用。现有 `examples/grading/suite.json` 只有一个示例，并依赖注册验证器，不能直接作为无额外配置的入门测试集。

## 3. 界面方案

1. 将文本断言与任务结果验收做成同层卡片，消除卡片套卡片；任务验收标题行放标题和带明确标签的启用控件，下一行仅保留简短说明。
2. 结果规则与行为规则分组显示数量。空组显示轻量空状态；行为组集中展示“当前不支持真实行为判分”的提示，规则默认可选，说明必要行为规则会被预检拒绝。
3. 规则类型选择与“添加规则”按钮同行，窄屏换行。每条规则以紧凑卡片展示类型、必要/可选状态和删除按钮，字段使用现有标签、输入框、间距和焦点样式。
4. 文件类常用参数提供表单：相对路径、比较方式、预期值、JSON Pointer 和数值容差。JSON 预期值保留类型，不能把数字 12 静默转为字符串。复杂行为参数保留带说明的 JSON 编辑；验证器沿用注册列表。
5. 规则 ID 和高级参数折叠展示，保留已有 label 及所有合法参数。整体 JSON 默认折叠，展开时载入当前规则，操作按钮同行；只保留一个折叠箭头。
6. 详情使用现有状态标签展示通过、失败、验证错误和证据不足；摘要显示必要条件通过数，每条规则展开查看预期、实际和证据。

## 4. 示例与插入方式

新增独立可导入案例集 `examples/grading/ui-examples.json`，所有案例显式指定完整任务模式，使用空工作区和完整工具范围，不依赖注册脚本。通过现有 API 在当前运行实例新建“判分规则示例”模块并导入，保留原有案例；同名示例存在时检查后跳过，避免重复插入。若当前实例不可用，则先启动本地服务并确认数据目录后导入，交付时说明位置。

| 示例 | 任务与规则 | 预期结果（Agent 按提示执行时） |
|---|---|---|
| JSON 汇总正确 | 生成 summary.json，检查存在、total=12、items 包含指定成员 | 通过 |
| 文本与禁止产物 | 生成含 Bun 且不含 npm 的说明，检查临时文件不存在 | 通过 |
| 数值容差 | 生成 ratio=0.3333，按 1/3 和绝对容差 0.001 验收 | 通过 |
| 只回复完成 | 明确只回复、不写文件，但验收要求 summary.json 存在 | 失败，定位缺少产物 |
| JSON 值不符 | 提示写入 total=10，但验收要求 12 | 失败，展示预期与实际 |
| 可选行为诊断 | 生成并检查文件，附可选工具次数规则 | 文件通过；行为证据不足，不改变任务判定 |

示例描述标明预期判定与用途；实际结果仍由执行产物决定。必要行为规则拒绝、文件保持不变及注册验证器继续使用现有测试或专门 fixture，不混入零配置示例。

## 5. 数据、兼容与异常处理

- 不新增后端接口或修改 grading version/schema，使用现有案例导入接口。
- 关闭任务验收仍不提交 grading；既有 assertions 与 grading 并存语义不变。
- 类型切换与添加/移除前保留已编辑数据；JSON 无效时保留输入并展示就近错误，不覆盖成空配置。
- 验证器列表异步加载只更新相应选择项，避免重建表单丢失焦点或输入；加载失败提供明确提示。
- 插入示例不复制凭据、不覆盖全局设置，不自动运行 Agent；实际运行使用用户已有模型配置。

## 6. 验收标准与实施步骤

1. 确认方案后调整 grading.ts、app.ts 和局部样式；保持其他页面样式稳定。
2. 添加示例集与说明，通过现有解析器及预检；验证预期通过/失败的固定产物，避免依赖模型输出来证明判分器正确。
3. 检查保存重开、添加删除、必要条件切换、JSON 编辑、不同类型预期值保真，以及异步验证器加载。
4. 运行 Bun typecheck 和相关判分/Web 测试；不修改 SDK，无需重建 SDK。
5. 浏览器验证桌面与窄屏、空状态及多规则状态，检查无横向溢出、双箭头和多余空白；不可用时如实记录限制。
6. 导入六个示例并核对列表及保存的规则，补充验证记录，将方案状态改为 Implemented。
